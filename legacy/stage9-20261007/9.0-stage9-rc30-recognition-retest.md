# rc.30：课表截图识别定向复测

## 状态与范围

当前候选：8.3.0-rc.30 / versionCode 564，分支 stage9/regression-freeze。目标为同一台 OPPO / ColorOS 17 / Android 17 测试设备。rc.29 的两张 AI 生成图失败；一条摘要 bytes=2627 sha256=336a4584ab syntax=false invalid-json。摘要不包含响应正文，不能定位具体格式问题。rc.30 只兼容可确定的外围文字/代码围栏/BOM/尾逗号，仍不能保证所有模型坏 JSON 都能修复。

本轮先测 P1-B 导入到审核，再测 P1-E 三种决策。不重跑已通过的 P2 外观、重启和 soak。

## 安装与准备

1. 仅下载本修复提交对应、全部门禁成功的 Actions 稳定签名 APK。不要复用 Run 551/561。记录运行编号、APK 文件名与 SHA256。
2. 在 PowerShell 执行 adb devices -l，选定唯一目标 serial。之后每条 adb 命令加 -s <serial>。
3. 执行 adb -s <serial> install -r <APK绝对路径>，必须输出 Success。禁止卸载、pm clear 或删私有数据。
4. 执行 adb -s <serial> shell dumpsys package com.sakata.focusflow，核对 versionName=8.3.0-rc.30、versionCode=564。
5. 启动应用，关闭本次更新说明。设置 → 高级工具 → 课表识别，确认 Qwen/Qwen3-VL-8B-Instruct 的 key 已保存、已通过能力测试且为默认。保持校园生活开启。不要重新输入 key 或写入证据。
6. 计划 → 课程，记录已确认/待确认计数作为基线。如果输入过文字，先收起软键盘，再读取 UI；不要套用旧屏幕坐标。

## P1-B：优先复测原图

1. 计划 → 课程 → 截图识别 → 显式选择服务 → 选择上次失败的第一张图。
2. 记录开始时间。应显示识别进度和“取消识别”。在 120 秒内等待结果，不反复点击或重复提交。
3. 出现审核页即记录：候选数、课程名、星期/节次是否为空、警告文案。先不要应用导入。
4. 退出审核，再以同样路径测试第二张原图。
5. 如果提示无法安全解析，完整复制括号里的 bytes / sha256 / syntax 摘要及错误文案，记录耗时；不要复制原始响应、key 或真实课表隐私。
6. 如果显示“没有识别到课程”，记录为模型未产出候选；这与语法解析失败不同。AI 生成图不保证文字/网格准确，补一张能清楚看见星期表头、节次和课程名称的真实截图再判断识别可用性，隐私图不上传到报告。
7. 两张图均无审核页：P1-B 失败，P1-E 未执行。退出后课程计数必须与基线一致。停止此链路并回传摘要，不用重跑 P2。

## P1-E：有候选后再测

仅在审核页确实出现至少三条可辨认候选时执行。候选少于三条则不冒充完整决策覆盖。

1. A 选择确认，检查星期/开始节次/结束节次有效且无冲突；空间依据不足时不得强行确认，先记为受阻。
2. B 选择编辑，清空或不填星期/节次，只改标题，提交编辑；B 应保持待核对、不可写入。
3. C 选择拒绝；C 不应写入。
4. 点击应用，只允许已确认 A 成为新增待确认课程；B/C 不应写入。核对课程计数与 A 的完整星期/节次范围，已有课程不应被静默覆盖。
5. 确认新增 A 为本轮测试数据后，在应用内删除该条，回到原课程计数。没有应用导入则不做清理。不要删除已有 16 门课程。

## 回传格式

- 安装版本、Actions run 编号、模型名。
- 图1：耗时 / 是否审核页 / 候选数 / 错误文案与完整摘要。
- 图2：同上。
- P1-E：A/B/C 各动作与实际写入；未满足前置条件就写未执行。
- 导入前后、清理后的已确认/待确认计数。
- 不把工程通过、部分手测或短 soak 写成 9.0 正式发布完成。
