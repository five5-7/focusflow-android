# vision key 提供方式（阶段9 验收用）

结论先说：**本项目没有构建期注入通道，key 只能从应用界面输入。**
但你**可能不需要新 key** —— 设备上已存的 key 是有效的，失败原因是账户余额（HTTP 402），
换一个免费模型就可能直接通过。详见第 3 节。

---

## 1. key 在本项目里怎么落地（读代码得出，非猜测）

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 有构建期注入吗？ | **没有** | `app/build.gradle.kts` 只有 `buildConfigField("String","CI_RUN_NUMBER",...)`，无 key 相关字段 |
| 有环境变量注入吗？ | **没有** | `Vision*.kt` 中无 `BuildConfig.` 读取 key，无 `System.getenv` |
| 有 local.properties 通道吗？ | **没有** | `local.properties` 只放 `sdk.dir` |
| 有 debug 专用入口吗？ | **没有** | 该页无 debug/release 分支差异 |
| 实际存哪？ | 运行期输入 → Android Keystore 加密 → SharedPreferences | `VisionCredentialStore.kt` |
| 加密细节 | AES-256/GCM，Keystore alias `focusflow.stage8.credentials.v1` | `AndroidVisionCipher` |
| 落盘文件 | `focusflow_credentials.xml`（SharedPreferences 名 `focusflow_credentials`） | 构造函数 |
| 会回显吗？ | **不会**，输入框是 `PasswordVisualTransformation`，保存后清空 | `VisionServicesUi.kt:81` |
| 备份会带走吗？ | 不会，已在 `backup_rules.xml` / `data_extraction_rules.xml` 排除 | 仓库 res/xml |

**关键推论**：密文是用**这台设备自己的 Keystore 私钥**加密的，
所以**无法从电脑上预置** `focusflow_credentials.xml`（写进去也解不开）。
**唯一入口就是应用界面。**

---

## 2. 怎么把 key 交给测试环境（两条路，任选）

### 路线 A：你直接在手机上输入（最安全，推荐）

1. 手机打开 FocusFlow → 设置 → 高级工具 → **课表识别（视觉模型）**
   - 前置：**通勤与地点 → 校园生活** 必须为「开」（本机已是「开」）
2. 找到 **硅基流动** 卡片 → 点 **编辑**
3. 在「key：留空保留已存值，填写后替换」输入框粘贴 key
   - ⚠️ 输入框留空 = 保留原值；**填了就替换**，原 key 不可恢复
   - 如果只想改模型不改 key，**这个框留空**
4. 点 **保存配置**
5. 告诉我「key 已输入」，我接着跑能力测试与后续验收

> 若你不想动已存的那把 key：把它当作有效 key 直接用即可，见第 3 节。

### 路线 B：放在工作区文件里，由我注入（key 不进入对话）

前提：**不要把 key 贴到聊天里**。放到工作区内、不属于 git 仓库的目录：

```
D:\focusflow\.secrets\vision-key.txt     ← 只放一行，key 原文，不要引号不要空格
```

注意 `D:\focusflow\.secrets\` **在 git 仓库之外**（仓库是 `D:\focusflow\focusflow-9.0\`），
所以不存在误提交风险。放好后告诉我「已放好」，我会：

1. 用脚本读取该文件，通过 `adb shell input text` 注入到聚焦的 key 输入框，
   **脚本不回显 key**，我的上下文里不会出现明文；
2. 注入后立刻 `删除该文件`；
3. 跑完验收后，在应用里点 **删除 key** 把设备上的凭据也清掉（可随时撤回）。

**两条路的取舍**：路线 A 的 key 完全不经过我的进程；路线 B 省你手动操作但 key 会短暂存在于设备输入通道。
如果你只是想让我把流程跑完，路线 A 更稳妥。

## 3. 也许你根本不用给新 key（重要）

本次真机实测中我直接点了 **能力测试**，结果是：

```
服务请求失败（402）
```

HTTP **402 = Payment Required**。这说明两件事：

1. **已存的 key 是真的、且能通过认证** —— 若是无效 key 会返回 401，并显示「认证失败，请检查 key 与服务权限」；
   现在返回 402，说明**认证这一关已经过了**。
2. **账户余额不足** —— 硅基流动对未充值账户调用付费模型返回 402。

当前配置的模型是 `Qwen/Qwen3-VL-32B-Instruct`（付费模型）。

### 所以最省事的做法

应用内帮助文本自己写着：「免费模型（如 **Qwen3-VL-8B**）无需充值」。

请你在 **同一页** 把模型换成免费模型再试：

1. 设置 → 高级工具 → 课表识别（视觉模型）→ 硅基流动卡片 → **编辑**
2. 把「视觉模型 ID」从 `Qwen/Qwen3-VL-32B-Instruct`
   改成免费模型 ID（可先点 **可选：获取模型列表** 看有哪些可用）
3. **key 输入框留空**（保留已存 key）→ **保存配置**
4. 点 **能力测试**

如果换成免费模型后能力测试通过，那么 **批次 A 成功路径、批次 B、批次 C 全部解锁**，
而且**一把新 key 都不需要**。

### 如果一定要新 key

那需要满足：① 账户**有余额**（或只用免费模型）；② key 未绑定包名/域名白名单
（本项目直连 `https://api.siliconflow.cn/v1`，非硅基流动的服务需自行填 HTTPS 根地址）。

## 4. key 用在哪些验收项上（供你决定值不值得给）

| 解锁的验收项 | 需要的条件 |
| --- | --- |
| 批次A-6 能力测试通过路径 | 有效 key + 有余额或免费模型 |
| 批次A-8 获取模型列表成功路径 | 同上 |
| 批次A-9a/9c「设默认」与导入前选择上传服务 | 同上 |
| 批次A-7b「取消识别」 | 同上 + 真实课表图 |
| **批次B 全部可见输出**（网格定位、预览告警） | 同上 + 真实课表图 |
| **批次C 全部 7 项**（审核/确认/编辑/拒绝/fail-closed） | 同上 + 真实课表图 |

**不依赖 key 的项**（我可以继续自己跑）：批次A-1/2/3/4/5/8失败路径/9b/10/11/14、日程任务、收集箱、回收站等。

## 5. 验收记录里的凭据来源标注约定

为满足「哪些结论是真实 key 跑出来的、哪些是免 key 跑出来的要能一眼分清」，本报告约定标注：

| 标记 | 含义 |
| --- | --- |
| `[真实凭据]` | 使用设备上已存的有效 key 真实请求了服务 |
| `[免key]` | 不涉及网络凭据的本地行为（UI、校验、持久化） |
| `[桩数据]` | 使用哑值/构造输入，服务端必然拒绝 |
| `[未执行]` | 本次没跑，不得视为通过 |

三类结果**分开记录，不合并成一份通过清单**。
