## 二、新发现

### 【P2-5】能力测试通过，但真实课表图片导入必然超时 —— 默认配置下功能不可用

- **现象**：能力测试通过（内部生成的小图，快），但用**真实尺寸课表图片**导入时，
  连续 **3 次**均以「服务响应超时，请稍后重试」失败。
- **复现步骤**（`[真实凭据]`）：
  1. 设置 → 高级工具 → 课表识别（视觉模型）→ 能力测试 → **通过**
  2. 计划 → 课程 → 截图识别 → 选择硅基流动 → 选一张课表图片
  3. 观察「正在识别课表」对话框
- **实际结果**：3 次尝试分别在约 **45s / 48s / 48s** 失败，文案「服务响应超时，请稍后重试」。
  图片分别为 1400×1800（90 KB）与 900×1150（79 KB），**缩小尺寸后仍然超时**。
- **预期结果**：默认配置（超时 60s + `Qwen/Qwen3-VL-32B-Instruct`）应能完成一次真实课表识别。
- **影响**：
  - **阶段8 批次B、批次C 的真机验收被这一条卡死** —— 进不了审核对话框，B1/B2/C1–C7 全部无法验证。
  - 用户视角：能力测试说「通过」，但实际导入用不了，属于**误导性的绿灯**。
- **等级**：**P2**（功能可用性；不涉及数据安全。若认定「默认可用的导入路径」是发布必需，可升为 P1）
- **建议**：
  1. 把「能力测试」的金标图从「本机生成的小图」改为**接近真实课表尺寸/复杂度**的样本，
     使能力测试能反映真实导入的耗时，避免绿灯误导；
  2. 复核默认 `timeoutSeconds=60` 是否足够，或对视觉请求使用更长的独立超时；
  3. 在超时文案里给出可操作指引（例如「可在服务配置中调大响应超时」）。
- **待确认**：本次未能排除是**当前网络到 api.siliconflow.cn 的上行带宽**导致。
  要坐实「超时是配置问题而非网络问题」，需把超时调到 120s 复跑一次（见第四节未完成项）。

### 【P3-5】视觉页帮助入口仍不可达（第1轮 P2-3 的现场确认）

- 第2轮实测中，该页**没有任何 `?` 帮助按钮**，「如何获取 key」按钮与
  `CourseVisionKeyGuideDialog` 在真机上确实不可达，与代码审计结论一致。
