## 0. 环境前提（影响全部结论的外推范围）

本次全部真机结论成立于 **Android 17 / ColorOS 17**，而 `docs/9.0-stage9-regression-matrix.md`
规定的目标环境是 **Android 15 / ColorOS 16**。维护者已决定**环境差异不作为阻塞项**，
因此本清单不再把环境列为阻断，但**每一项设备侧结论都只在下列前提内成立**：

| 维度 | 本次实际 | 规定 | 外推风险 |
| --- | --- | --- | --- |
| 系统 API | 37 | 35（Android 15） | 通知渠道行为、后台限制、精确闹钟门控均随 API 变化 |
| ColorOS | V17.0.0 | 16 | OPPO 后台保活/自启/通知折叠策略为厂商私有实现，跨版本不保证一致 |
| 应用 targetSdk | 35 | 35 | 应用以兼容模式运行在 SDK 37 上，系统会施加 targetSdk 门控 |
| 应用 compileSdk | 36 | — | 实机 API 37 **高于** compileSdk，存在未经编译期验证的系统行为 |

**结论外推规则**：凡标注 `[设备相关]` 的通过项，**不得**直接写进 Android 15 / ColorOS 16 的验收记录。

## A. 必须使用真实凭据才能进入的路径

### A1. 视觉服务能力测试「通过路径」
- **缺什么**：一个真实可用的 OpenAI 兼容视觉服务 key（如硅基流动 `sk-` 开头）。
- **为什么没覆盖**：`设默认` 按钮 `enabled = p.id in available`，而 `available` 只包含**通过能力测试**的服务；
  没有有效 key 时能力测试必然失败，因此「设为默认 → 导入时选择上传服务 → 进入审核」整条链路无法进入。
- **影响面**：**阶段8 批次A 的核心成功路径、批次B 全部可见输出、批次C 全部 7 项**都被这一个前置卡住。
- **可验的替代**：失败路径可验（无效 key → 「认证失败，请检查 key 与服务权限」，行保持「待测试或凭据不可读」，
  `设默认` 保持禁用）。本次**未执行**该失败路径。
- **补做条件**：真实 key + 少量额度（能力测试会发真实请求，用本机生成的小图，可能产生费用）。

### A2. 审核对话框与批次B 输出的唯一可见入口
- **缺什么**：同 A1，且需要**真实课表图片**。
- **未覆盖项**：
  - 「检查课表识别」对话框入口（批次C-1）
  - 逐条 确认 / 编辑 / 拒绝（C-2 / C-3 / C-4）
  - fail-closed：不做决定、重复决定、未知候选（C-5）
  - 「应用审核结果」→ 待确认课程路径（C-6）、「取消」（C-7）
  - 网格定位文本 `候选 <id> · 定位：周X 第Y-Z节` / `无法唯一定位`（B-1）
  - 预览告警「图像几何信息无效」「部分候选框无法映射，需人工检查」「部分候选无法唯一定位到星期或节次」（B-2）
- **影响面**：阶段8 批次B、批次C 的**用户可见行为完全未经真机验证**；
  现有证据只有 Run 545 的单测，属于「工程门禁」，不能替代真机。
- **补做条件**：A1 的真实 key + 至少 1 张真实课表照片（及 1 张故意缺表头/倾斜的样本）。

### A3. 两个真实供应商 API 的边界行为
- **缺什么**：两家真实可用服务的账号与 key。
- **未覆盖**：能力测试金标图往返、严格响应校验、超时、取消、3xx 拒绝、字节预算、错误分类（批次A-11/A-12）。
- **注意**：其中 **A-11 错误分类**（DNS 失败 / 404 / 3xx / SSL / 超时）理论上**不需要有效 key**，
  用假地址即可覆盖，本次**未执行**——这是**低成本可补**的一项，建议优先补。

### A4. 教务导入（浙大）
- **缺什么**：真实浙大账号 + 教务系统可达网络。
- **未覆盖**：当前学期导入、指定学期导入（学年起始年 + 秋冬/春夏/短学期）、导入失败处理、
  重复导入去重、登录阶段 40 秒看门狗、导入页可退出。
- **影响面**：阶段6 的核心用户路径，同时是**重复导入去重**这类数据安全行为的唯一验证途径。
- **补做条件**：真实账号；注意凭据仅用于本次会话，不落盘。

### A5. 学习路径建议 / 教程联网搜索
- **缺什么**：共享 key（同 A1）。
- **未覆盖**：联网搜索成功路径、「共享 key 同时用于视觉识别与学习建议」的联动、「删除共享 key 后两者都不可用」。

## B. 需要 root 或可调试包才能触发的路径

### B1. 「重试未确认的保存」与「配置损坏保留原文」（批次A-13）
- **缺什么**：能让 `configuration == null` 的手段。
- **为什么没覆盖**：应用**没有任何 UI 入口**能损坏服务配置（无导入/编辑原始 JSON），
  因此「重试未确认的保存」按钮在单机上点不出来。
- **补做条件**：root 设备直接改 `/data/data/com.sakata.focusflow/shared_prefs/focusflow_vision_services.xml`，
  或使用 **debug 包**（但 AGENTS.md 规定验收只能用稳定签名包，会与验收口径冲突）。
- **影响面**：无法确认「配置损坏时保留原文、不覆盖为空配置」这条防丢失承诺在真机成立。

### B2. Keystore 密文与备份排除规则的实际效果（批次A-14 的后半）
- **缺什么**：可读取 `focusflow_credentials.xml` 的权限，或第二台设备。
- **未覆盖**：
  - 换机后重填、Keystore 密钥失效后重填
  - `backup_rules.xml` / `data_extraction_rules.xml` 排除规则在云备份/迁移中的**真实效果**
  - 密文文件实际内容与 alias `focusflow.stage8.credentials.v1` 的落盘形态
- **可补的低成本部分**：A-14 的「旧明文 key → 同机覆盖安装后迁移」只需**哑值**即可验证
  （装旧版填任意 key → 覆盖安装候选 → 卡片应显示「key 已保存」且不回显明文）。本次**未执行**。

### B3. Room 真实数据库文件
- **缺什么**：root，或 Room 产品激活。
- **说明**：契约明确 **Room 产品激活保持关闭**，不属本候选；本次未纳入，也不应纳入发布门禁。

## C. 依赖规定机型 / 系统版本才能验证的行为

> 以下即便在 Android 17 上通过，也**不能**直接作为 Android 15 / ColorOS 16 的证据。

### C1. 通知与后台（`[设备相关]`）
- **已覆盖**：锁屏 + 从最近任务划掉后送达，延迟 ≤8 秒；5 个通知渠道注册；前台服务常驻通知。
- **未覆盖**：
  - **APP 前台**、**APP 后台（未杀）**两种状态未单独计时
  - 开机恢复（`RECEIVE_BOOT_COMPLETED` + ColorOS 开机广播推迟）— 代码注释明确提到 ColorOS 会推迟开机广播
  - 餐次提醒 dismiss、活动结束通知、错过任务摘要
  - **Doze / 省电模式下的延迟上限**：本次已发现 `STANDALONE_DUE` 为非精确闹钟
    （`window=+3m19s`、`maxWhenElapsed=+6m40s`），需在 Doze 下取样本才能定性最坏延迟
  - 连续多天运行后的闹钟漂移
- **外推风险**：ColorOS 的自启管理、后台冻结、通知折叠为厂商私有实现，16 与 17 行为不保证一致。

### C2. UI / 材质回归矩阵（`[设备相关]`，需求决策 v0.22 要求）
- **已覆盖**：仅「页面背景=图片 + 卡片材质=毛玻璃」下**快速入门弹窗**一项（像素级验证通过）。
- **未覆盖**（矩阵显式要求，当前**零设备证据**）：
  - 四种页面背景：默认 / 渐变 / 亚克力 / 图片背景
  - 五种卡片材质：默认 / 渐变 / 柔光 / 亚克力 / 毛玻璃
  - 覆盖对象：页面、弹窗、底部面板、展开状态、选择工具栏
  - 三种动效状态：丰富动画 / 简化动画 / 系统「移除动态效果」
  - 大字体、窄屏、键盘避让
  - 明暗模式、章节前后切换与滚动恢复、关闭动画
  - 批量选择交互
- **影响面**：这是需求决策 v0.22 的**主干验收内容**，目前基本空白。

### C3. 课表识别输出与坐标验证
- 真实图片识别准确率、拍屏透视样本 — 契约明确**批次B 未实现 OCR**，4.0.1 起已无本地 OCR、无降级路径。
- **属于「功能未交付」而非「未测试」**，不应计入验收缺失，但**必须在发布说明中如实表述**。

### C4. 至少一天连续使用验收
- **VERSIONING.md 发布流程第 4 条**明确要求「完成覆盖安装、旧数据、目标设备通知和**至少一天连续使用**验收」。
- 本次为单次会话验收，**未满足**该条。
- 影响：长期运行下的内存、闹钟漂移、通知渠道被系统降级、数据增长等问题无证据。
