## 3. 缺陷清单

### A. 验收脚本不可执行（阻断级，4 个独立缺陷）

包内文档的入口是 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dsh-stage9-fast-acceptance.ps1`，即 **Windows PowerShell 5.1**。该脚本**按原样无法运行**，与设备、网络、签名无关：

| ID | 缺陷 | 证据 |
| --- | --- | --- |
| D-1 | 脚本 **UTF-8 无 BOM** 且含中文串字面量；PS 5.1 按 ANSI(GBK) 读取 → 解析器大面积报错 | `evidence/script-defects/d1-no-bom.out` |
| D-2 | 第 112–114 行在可展开字符串内嵌双引号（`"size=$((…) -join " ")"`）→ `TerminatorExpectedAtEndOfString` | `evidence/script-defects/d2-nested-quotes.out` |
| D-3 | `Run-Git/Invoke-Adb` 用 `$Args` 作参数名，与自动变量冲突，`@Args` 展开为空 → **git/adb 收不到子命令**（与解释器版本无关） | `evidence/script-defects/d3-args-splat.out` |
| D-4 | `$ErrorActionPreference="Stop"` 与 `& native 2>&1` 组合，使 git 正常 stderr 进度变成终止性 `NativeCommandError` | `evidence/script-defects/d4-eap.out` |

**最小修复**（BOM + 引号 + 参数改名 + 原生调用局部放宽 EAP，不改任何门禁判据）已跑通 P0-A：
- 修复脚本 `tools/dsh-stage9-fast-acceptance.ps1`（sha256 `425785015541ea5f766792b17b0fb8a134c27a5c03708ee5500c0df7bf57d7b3`）
- 说明与 diff：`tools/PATCH-NOTES.txt`；可复现补丁器 `tools/make-patched-script.py`
- 原始件 sha256 `e42fea906e7fded14ffaab6b108d8252c4d460808135700a7a939620f1aa220b`

## 7. 并发执行说明（正面回答「手机上能否做到应用并发」）

### 7.1 设备层：能不能同时跑多个应用/分屏

- ColorOS 17 / Android 17 **支持**分屏、小窗、悬浮窗；但这些是**同一个应用实例占一个窗口**，不是两个实例。同一包名同一用户默认只有一条任务栈，再次启动只是把已有实例拉到前台。
- 真正的"两个实例"只能靠**应用分身/双开**，会创建独立用户空间的第二份数据（且 OPPO 只对白名单应用开放）。本机实测 `pm list users` **只有 user 0**，无分身用户。对验收而言双开反而破坏了数据前提，故未采用。
- 结论：**"同时跑两个 FocusFlow 做并发验收"在这台机上行不通**；应用侧并发只体现为「一个前台 UI + 后台闹钟/通知」，这一点 P2-A 已实测成立（进程被杀后提醒仍触发）。

### 7.2 验收任务层：哪些能并行、哪些只能串行

| 类别 | 能否并行 | 原因 |
| --- | --- | --- |
| 所有 UI 驱动用例（`input tap/swipe/text`） | **只能串行** | 注入目标是**全局聚焦窗口**；`uiautomator dump` 与 `screencap` 抓的是**整屏**，两条 UI 用例会互相污染 |
| 被动观测（`logcat` 流、`dumpsys notification/alarm/meminfo/gfxinfo`） | **可与 UI 用例并行** | 只读、不改变前台；但观测的是全局状态，需时间戳分段归因 |
| `adb reboot` | **设备级独占** | 重启窗口内设备侧无任何可用通道 |
| 长等待（提醒倒计时、soak） | **只能交错** | 等待期本身不占设备，可用于 PC 侧工作 |

### 7.3 本次实际采用的编排（等待窗口交错）

| 等待窗 | 同时进行的工作 |
| --- | --- |
| 提醒 #2 倒计时（约 2 分钟） | 以独立后台进程轮询通知状态（被动观测），同时准备 P2-B 脚本 |
| `adb reboot`（33.4 s） | 不做设备侧操作；用于整理证据与报告 |
| P2-C 压缩 soak（约 25 分钟） | soak 独占设备 UI；PC 侧并行改写报告。期间 soak 自身**检测到真实提醒触发**（21:24:13），即"等待窗内嵌观测" |

**并发带来的一个真实代价（已记录）**：soak 在高频 UI 注入的同时反复调用 `dumpsys meminfo`，其中一次返回超过 90 s 触发超时并中断 soak。这说明**同一条 adb 通道上"高频 UI 注入 + 重量级 dumpsys"会互相拖慢**——后续编排应把重量级采样降频（本次约每 79 s 一次仍不够）或改用 `gfxinfo`/`logcat` 这类轻量通道。

**证据可归因性保障**：每条用例的结论都绑定到自己的 dump/JSON 与时间戳；课程计数（16/0）、视觉服务配置、应用前台/进程状态在每条用例前后各取一次快照，确认未被其他用例污染。全程未执行 `pm clear` / 卸载 / 删私有数据。
