## 二A、实际执行摘要：模型、工作方式与验收

### 模型规则

- 主模型使用 `GPT-5.6-sol`；审计、数据迁移、通知、课表识别和跨模块整合使用 high reasoning。
- 边界明确的Compose界面实现、动画迁移和机械性测试补全可使用 `GPT-5.6-terra` high；每个检查点完成后由 `GPT-5.6-sol` 复核，不在同一小任务中频繁切换。
- `GPT-5.6-luna` 只用于格式整理、静态扫描结果归类等不改变业务语义的工作。
- 常规路线不使用 Astra。只有问题已经稳定复现、连续两轮修复失败且判断为架构级阻塞时，才先报告证据并询问是否切换；不得自动消耗 Astra 额度。

### 外部 AI 分流试跑（减少本账户额度）

- 用户希望减少**本 ChatGPT Work／Codex 账户**的额度消耗；本账户内切换 Luna／Terra 仍计入同一用量，不视作完成分流。优先把单一边界、可独立验收的静态审计／测试矩阵／局部纯 Kotlin 测试交给外部独立额度：代码工作可先试 DeepSeek API `deepseek-flash` 搭配可读写仓库的工具；少数静态文件的整理同样先用已有 DeepSeek 额度。外部 API 的费用、免费层限制及数据使用政策需单独评估，不得代用户开通付费服务或外传密钥。
- 高风险的课程身份、多课次与 Room 迁移、通知调度、恢复性删除仍由当前账户的 Sol 审定设计和关键差异；外部 AI 执行时必须有明确输入、停止条件、测试门禁与可审查的单项提交。先用一项阶段6测试缺口矩阵试跑，衡量返工与本账户用量，验收后才扩大范围。可复制任务与完整本地快照交接见仓库 `docs/9.0-ai-handoff.md`。
- 外部用量的默认编码入口为 DeepSeek Flash＋OpenCode：Plan 核对证据与边界，Build 做限定范围修改，测试／CI／真机验收。已收到 C 对阶段6测试缺口矩阵的只读报告，并基于 818bd74 快照复核：10 个测试名存在；夏令时测试尚未覆盖跨切换周的 nextTrigger；QuietHoursTest 的 4 个基础测试应计入覆盖范围；接收端无效 ID、无效时间和未来广播会在 restore 前返回，C 的“先于一切检查”表述不准确。B 在用户电脑上生成的 docs/9.0-stage6-test-gaps.md 尚未提供，不能核实其中所有行号和措辞；先做文档更正，再分项决定新增测试。不得把模型发现当作已修复。需要不同模型的独立复核时，可选 GLM 普通 API＋OpenCode Plan，或在已有额度时使用国内 GLM Coding Plan／真正 Claude；GLM 普通 API 与 Coding Plan 的密钥、入口和费用分别核对，不代用户开通或付款。若 Claude CLI 仍连接 DeepSeek，只是另一工作台。DeepSeek Harness 仍为开发预览，Aider 适合小范围补丁；不为每项小改动固定堆叠多个模型。外部工具选择以本文件当前版本为准；仓库旧交接单若列出其他默认入口，先按本段执行。

### 多模型协作与自动化路线（L1→L2）

- L1（已配置，2026-09-26）：OpenCode 接入 SiliconFlow provider（OpenAI 兼容，key 走 `{env:SILICONFLOW_API_KEY}`，白名单 GLM-5.3／Kimi-K2.7-Code／Qwen3-Coder-30B／Qwen3-VL-8B）；只读审查子代理 `review`（GLM-5.3）与 `review-kimi`（Kimi-K2.7-Code，`edit: deny`、`bash: ask`）；启用内置 `websearch`（`OPENCODE_ENABLE_EXA=1`，免 key）；批量模型暂缓启用。规则与配置见仓库 `docs/9.0-ai-collaboration.md`。
- L2（2026-09-27 本地实现，待重启烟测）：①提交前自动审查（`review-gate` 拦截 `git commit`，只读 `review` 子代理审查暂存差异，同 diff 哈希只审一次，缺陷阻止提交，服务不可用时放行并提示）；②后台任务工具（`bg_start`/`bg_status`/`bg_stop`，长构建后台化＋完成/失败通知，命令走 bash 权限规则）；③模型发现（启动同步 SiliconFlow 可用列表，移除下线白名单并警告；默认不自动新增，可选 `include` 通配符扩展）；④通知强化（opencode-notify 已覆盖需确认/失败/完成，仅核对配置）。插件位于 `D:\focusflow\.opencode\plugin\`，配置与烟测清单见 `docs/9.0-ai-collaboration.md` 第 4／5 节。
- L2 边界：仍不自动 commit／push／发布；审查者只读且独立；高风险设计先由主模型审定。L3（自动循环修复、自动提交）明确不做。

### 统一工作方式

每个检查点固定执行：读取当前计划与分支 → 审计相关代码和数据 → 写出本检查点变更边界 → 实现 → 单元/回归测试 → Debug与Release构建 → 签名、版本和APK核验 → 真机任务 → 记录结果后进入下一检查点。8.3真机验收收口后可在独立9.0分支开展审计；未发布状态不阻塞分支隔离后的9.0审计，但正式合并与发布仍需用户单独确认。9.0按数据底座、统一组件、功能页面的顺序渐进迁移，不进行一次性大爆炸重写。

## 八、阶段4：收集箱、待办与计划闭环

### 检查点A：收集箱与待办

- 快速记录默认进入收集箱。
- 今日页收集箱使用一个共享材质容器：单行快速输入、总数、查看全部和最近两条单行摘要。
- 摘要只显示标题与弱化相对时间，长文本省略；点击后再进入详情或完整列表处理。
- 空状态只保留快速输入；新增内容以轻量过渡进入预览，不嵌套两张完整卡片。
- 完整列表将更早内容归入“之前记录”，仅按记录年龄分组，不标记为过时或逾期。
- 整理模式默认最旧在前，支持批量转待办、想做、计划、信息、删除和暂时保留。
- 为“暂时保留”记录最近回顾时间，同时保留原创建时间；汇总回顾避免重复推送同一批内容。
- 不自动删除或归档旧内容；可选汇总提醒只显示数量和时间事实。
- 单项默认显示紧凑摘要，点击后仅展开一个项目，并显示转待办、放入想做和更多。
- 加入计划、保存为信息、编辑和删除放入“更多”，不让低频按钮长期占据列表空间。
- 进入多选时收起展开项；复选框、计数、操作栏及单项尺寸/材质变化使用统一过渡。
- 收集箱转待办、计划或信息。
- 新建一次性待办。
- 新建待办只强制标题，首屏提供日期/今天、重复和提醒等少量快捷项，详细字段按需展开。
- 今日页、待办总列表、计划页和全局加号按已确认规则提供不同且可见的默认值。
- 支持检查清单，以及一次粘贴多行后生成多个待办或多个检查项。
- 普通完成和勾选检查项不弹确认；操作后提供撤回，活动记录保持可选。
- 未安排、已安排、逾期和已完成统一列表。
- 总列表默认展示全部未完成事项，清楚区分逾期、已安排和未安排，已完成折叠。
- 提供低干扰整理模式，支持批量完成、改期、改为未安排和取消。
- 待办项实现标题主行＋至多一行状态摘要；完整备注、设置和低频操作进入详情。
- 按异常状态、安排时间、临近截止、所属计划、重复/提醒/检查项进度的顺序裁剪元数据。
- 同组待办共享表面与紧凑分隔，分组标题显示数量并可折叠，避免每项独立大卡片。
- 勾选直接完成、点击详情、长按多选；计划列表同样采用名称＋一行事实摘要。
- 安排时间与截止时间。
- 新全局加号菜单：顶部快速输入默认收集箱，下方待办、计划、日程、提醒2×2排列。
- 单项软删除与立即撤回。

### 检查点B：计划

- 计划只强制名称。
- 可选目标/期望结果、说明和截止日期。
- 计划状态包含想做、进行中、暂停和已完成；“想做”不进入任务与逾期统计。
- 收集箱支持一键转为“想做”，以及多选内容后合并创建计划；原内容先进入想法/笔记区。
- “想做”可转为进行中，并可选建立近期任务；暂停计划不自动退回“想做”。
- 增加可关闭、可调整周期的低频汇总回顾，默认按月提示查看“想做”列表。
- 近期、稍后、已完成任务。
- 多个近期任务和可选当前重点。
- 计划进行中、暂停、已完成。
- 旧目标、逐步推进和下一步迁移结果可见。

### 最小真机任务

1. 快速记录一件事。
2. 转成待办。
3. 安排到今天并设置截止时间。
4. 加入计划。
5. 完成、取消、改期或删除后撤回。

## 九、阶段5：活动、重复任务与今日/明日视图

### 活动

- 不再提供全局“开始活动”或临时活动主流程。
- 待办详情的“更多”保留可选开始计时；普通任务默认不显示计时控制。
- 已有计时进行中时进入当前控制，不允许并行创建第二个计时。
- 暂停、继续、仅结束本次、完成任务、改期后结束。
- 多段活动汇总到同一待办。
- 保留已有活动历史；无记录时不显示空统计，任务完成、推荐、通勤、提醒和空挡计算不依赖活动日志。
- 将原“开始活动”旁的权限入口迁移为今日页紧凑“后台与提醒状态”，仅在权限缺失时显示；关闭提醒后只保留设置入口。

### 统计降级

- 移除统计的主界面入口、空统计卡和综合生产力评分，不为低使用率模块继续扩展独立页面。
- 保留完成、跳过、未处理、改期和既有活动历史的数据兼容性。
- 在待办、重复规则和计划详情中按需显示简要历史；没有活动日志时不显示时长区块。
- 验证旧数据升级后仍可访问，不因隐藏入口而删除或清空。

### 重复

- 重复规则生成实例。
- 实例区分完成、跳过、未处理、改期和删除。
- 规则区分暂停、停止和删除。
- 暂停期间不生成实例、不进入执行率分母。
- 条件重复支持“复习今天课程”。

### 今日与改期

- 今日页按已确认结构重组。
- 移除“下一件合适的事”卡片及其推荐入口，不替换为另一张智能推荐卡。
- 用户主动设置的当前重点可作为事实显示；课程、日程、待办和需要处理直接进入相应分组。
- 页面顺序优先为当前/即将发生的课程与固定日程、今天已安排待办，再显示需要处理和收集箱。
- 需要处理使用紧凑汇总并位于收集箱之前；已完成折叠，明天预览放在页面后部。
- 权限异常只在确实缺失时插入顶部附近，正常状态不保留占位。
- 增加紧凑明天预览，首版最多显示最早两项和剩余数量；不在今日页内展开，点击直接进入完整明日页面。
- 弹性任务直接显示有效范围。
- 错过安排后保留原时间并进入“需要处理”，原时段结束后停止占用未来时间轴和空挡计算。
- 今日页只显示紧凑的待处理汇总入口，不把旧任务卡推入后续日程空间。
- 原定开始提醒后，时段结束仍未处理时再提醒一次；之后保持应用内标记，次日按组汇总提醒。
- 临近截止时间或用户明确开启持续提醒时才追加单项通知，避免周期性催促。
- 多选今日剩余任务。
- 批量移到明天、选择日期、改为未安排、取消。
- 批量操作整批撤回。

## 十、阶段6：课程、通知与自定义提醒

### 课程

- 一门课程拥有多个上课时段。
- 教务导入优先按课程/教学班稳定编号与学期匹配。
- 支持手动合并、拆分和添加时段。
- 编辑区分单次、该时段后续和整门课程。

### 通知

- 课程提醒总开关与单课程覆盖。
- 课程提醒显示课程名、开始时间和该次地点。
- 临时换教室后使用更新地点。
- 统一课程、待办、日程和自定义提醒调度。
- 自定义提醒支持完成、稍后、移入收集箱、开始、打开中的至多三个动作。
- “稍后”只移动通知，不改变任务时间。

## 十一、阶段7：撤回与回收站

- 普通删除立即撤回。
- 批量、计划、课程、重复规则删除前确认。
- 回收站默认保留30天。
- 支持逐项恢复、永久删除和清空。
- 计划及所选内部任务可成组恢复。
- 课程恢复包含时段、颜色、通知设置和临时调整。
- 恢复后只重建未来通知。
- 课程合并/拆分、批量完成和批量改期支持整批撤回。

## 十二、阶段8：自定义模型与完整课表识别

### 自定义服务

- 内置模型与自定义服务切换。
- 显示名称、Base URL、API协议、API Key、模型ID和超时。
- 第一阶段支持OpenAI兼容Chat Completions视觉接口。
- API Key使用Android Keystore，界面只显示掩码且不写日志。
- 明确告知第三方服务会接收课表图片。

### 能力验证

- 测试连接。
- 获取模型列表或手动输入模型ID。
- 测试图片输入。
- 测试结构化输出。
- 未通过测试的模型不能设为默认。
- 不经用户同意，不在失败后静默切换第三方服务。

### 完整识别管线

- 图片质量检查。
- 旋转、透视和对比度处理。
- 星期列和节次行定位。
- 按列或区域识别课程块。
- 输出坐标、文字和几何置信度。
- 硬性校验后生成`Course＋CourseMeetingRule`。
- 将失败拆分为图片不完整、星期栏缺失、节次栏缺失、网格方向异常、课程块无法定位、模型格式错误、网络或服务错误，不再只显示笼统的“识别失败”。
- 失败提示应明确列出一张可识别课表必须包含的元素：顶部连续星期标题、左侧连续节次标签、完整课程网格和清晰可辨的课程文字；根据实际缺失项给出重新截图、减少裁切、校正方向或更换清晰图片的建议。
- 网格证据采用分级置信度与人工确认兜底，避免再次把缺表头图片误接收，也避免像rc.13一样因一次模型坐标输出不稳定而拒绝原本正常的完整课表。

## 十三、阶段9：综合回归与发布

### 自动验证

- 重复任务边界日期与状态。
- 通知注册、取消、恢复和重启。
- 批量操作逆向恢复。

## 十四、尚需确认的界面决策

以下问题不影响当前业务模型，但应在对应页面实现前确认：

1. 统一待办列表从哪里进入：改造现有“计划”底部入口，还是在计划页内增加“待办/计划”分段。

5. 是否允许将用户提供的课表图片作为私有仓库测试样本；未授权前只使用本地或合成样本。
6. 9.0确定提高材质可调的最大不透明度；具体新上限需先审计当前各控件范围，再用默认、渐变、亚克力和图片背景真机对比后冻结。
