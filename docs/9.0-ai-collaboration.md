## 3. 协作规则（长期有效）

1. 计划 → 实现 → 审查依次进行；同一时间只有一个写代码者。
2. 审查者只读且独立（不同模型族）；审查模型不兼实现者。
3. 一次只给一个外部 AI 一个任务边界；并行必须使用独立 worktree、互不重叠文件。
4. 密钥只放环境变量或 OpenCode 凭据库；仓库文件只引用 `{env:...}`，不写明文。
5. 测试、CI、真机是唯一验收证据；未执行必须写“未执行”。
6. 高风险（课程身份、Room 迁移、通知调度、恢复性删除）先由主模型审定设计与失败回滚，再实现。
7. 提交、推送、发布仍需用户确认；每批提交后导出时间戳 bundle 并登记 `D:\focusflow\backups\backup-log.md`。
8. 本文件与《AI 使用手册》《实施计划》《AI 交接单》同步维护；配置变更必须同步到本文件，保证可复现。

## 4. 自动化分级与路线

- **L1（当前）**：角色分工 + 模型路由 + 只读审查权限 + 内置搜索；审查由主代理或用户手动触发；提交/推送/发布人工确认。
- **L2（已列入实施计划）**：
  1. 事件钩子自动触发审查（插件：在实现完成或提交前自动调用 review 子代理）；
  2. 后台任务工具（`bg_start`/`bg_status`/`bg_stop`，长构建后台化 + 通知）；
  3. 模型发现插件自动同步 SiliconFlow 模型列表（替代手写白名单）；
  4. 通知强化（完成/失败/需要确认时弹窗）。
  以上均**不自动 commit/push**。
- **L3（不允许）**：自动循环修复、自动提交或发布；与“未经确认不合并/发布、高风险先审定”的仓库规则冲突。

## 5. 验证与回滚

- 重启 opencode 后：`/models` 应出现 SiliconFlow 的 4 个模型；调用 `review` 子代理复核一次小 diff；`websearch` 应可用（免 key）。
- 回滚：删除 provider/agent 配置或对应文件、清除 `OPENCODE_ENABLE_EXA` 即可；配置文件改动不触碰仓库与用户数据。
- 费用：审查一次典型 diff（数万输入 token）GLM-5.3 约 $0.05–0.1；Kimi 相近；以控制台账单为准。搜索走内置免费。
