## 边界和数据契约

- `Course.id` 是课次 ID，仍用于闹钟、单次地点、开关和旧通知。`courseId` 是本地课程父 ID；旧 JSON 缺少字段时默认等于原 `id`，不改旧数据。已显式归组的多个课次可共用父 ID；删除父 ID 对应的课次后，父 ID 可以留作本地稳定身份。
- 学年、学期、`xkkh` 候选值仅是导入来源提示。它们不能自行认定跨次导入后身份稳定；导入先生成独立待确认课次，用户核对后才归组。同名不同班不能按名称自动归组；更改的星期或节次不能凭 `xkkh` 覆盖既有课次。
- Room v6→v7 给课次规则添加三个来源列，旧行默认为空；父课程和课次规则改成一对多投影。Room 产品激活仍关闭。阶段 7.1/7.2 的普通删除与恢复能力在本分支基线内，迁移链保留顺序。
- 用户可核对候选后归组；已确认课次可手动归组、分离，整门课可统一改名；单次地点、此时段后续编辑以及相邻时段实体合并沿用既有入口。独立提醒通知正文仍打开应用；第三个通知动作改为“移入收集箱”，与应用内同一写入路径。`开始`没有目标对象定义，仍不提供后台动作。

## 给本地 AI 的执行指令

只使用此分支经 CI 稳定签名的 APK 覆盖安装现有应用。先备份用户数据；不清除数据、不重装、不合并 PR、不发布。设备是 OPPO / ColorOS 16 / Android 15。逐项记录：设备时间、版本号、操作、预期、实际、截图或日志、是否通过。发现失败则停止相关链路，保留数据与原始日志，返回最小复现步骤和文件路径，不靠改用户数据掩盖失败。

1. **旧数据迁移**：覆盖安装前后核对任务、课程、目标、提醒和临时地点数量；旧课程逐条 ID、启停、生效期不变。同名不同班不自动归为一门；重启再核对。
2. **导入与手动归组**：导入当前指定学期课表，核对同一 `xkkh` 的两节课只出现“候选”提示，手动确认后显示一门课程多课次；不同 `xkkh` 或不同学期不自动归组。再次导入相同课表，不得添加重复课次、替换旧 ID；如果教务变更节次，只新增待确认候选而不覆盖旧课次。验证分离与再归组、整门改名、单课次改名后的分离、删除父 ID 对应课次后其余课次仍在。
3. **课程提醒和地点**：确认学校节次表前开总开关不得按参考时间提醒；确认后核对提前 10 分钟、地点和两课次独立开关。单次临时地点只影响对应课次和日期，下周恢复固定地点；通知已发后改地点不二次弹。修改节次、停用、删课后旧广播不弹。重启、时区和系统时间变化后恢复未来提醒；静音与权限拒绝时下一周闹钟仍能恢复。分别测精确闹钟可用与不可用分支。
4. **编辑范围与通知**：单次地点、此时段后续日期拆分、相邻同节次合并的原 ID 和覆盖迁移均核对；确认合并前检查冲突地点计数和不可撤销提示。独立提醒“稍后”不改原时间，旧通知动作不影响新轮次；通知上的“移入收集箱”只创建一个收集箱项且完成提醒，重复点、重启后无重复；正文点击仍打开应用。通知权限、渠道、前后台及重启按真实触发时间记录。
5. **键盘与浮栏**：在今日页收集箱输入时调出键盘，底部栏确实浮在键盘上，正文卡片允许被它遮挡，但内容滚动与底栏应属于同一布局，不得出现截图所示独立于页面的“假悬浮”截断；收键盘后再核对。
