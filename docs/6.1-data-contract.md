# FocusFlow 6.1 本地数据契约

状态：6.2 重构兼容基线 · 6.5 任务历史事件（`task_events`）  
来源：`PrototypeStore` 及相关 codec  
SharedPreferences 文件：`focusflow`

## 兼容原则

- 已存在的 key 不改名、不复用为其他含义。
- JSON 新字段必须使用 `opt*` 读取并提供旧版本默认值。
- 读取损坏数据时保持当前降级策略：返回安全默认值，不覆盖原始值。
- 只有经过独立迁移和回归测试后才允许改变存储结构。
- API key、地图 key 与签名凭据不得进入日志、测试夹具或版本库。

## 核心对象

| Key | 类型 | 用途 | 6.2 约束 |
|---|---|---|---|
| `items` | JSON array | 收集箱、任务、完成记录和弹性窗口 | ID、完成状态、时间与目标关联必须保留 |
| `courses` | JSON array | 课程和待确认课程 | `needsConfirmation` 缺失时为 `false` |
| `course_setup_done` | Boolean | 是否完成过课程设置 | 不根据空课表反推为未设置 |
| `goals` | JSON array | 目标、周进度、执行依据 | 由 `StoredGoalsCodec` 维护旧字段默认值 |
| `resources` | JSON array | 学习资料 | 由 `StoredGoalsCodec` 维护；旧 `selected` 仍读取但不再自动套用 |
| `feedback` | JSON array | 任务完成反馈 | 与 `goalId` 的关联保留 |
| `sessions` | JSON array | 当前/历史活动模式 | 重启恢复依赖状态和结束时间 |
| `game_sessions` | JSON array | 空闲活动与前台检测记录 | 旧记录缺少分类时默认“游戏” |
| `status_checkins` | JSON array | 精力与所处活动签到 | 仅用户确认的数据参与学习 |
| `meal_records` | JSON array | 用餐开始/结束、可选消费与评价 | 缺失金额为 `-1`，评分限制为 0–5 |
| `baseline_profile` | JSON object | 当前生活阶段与作息基线 | 缺失时返回空白 `BaselineProfile` |
| `baseline_variants` | JSON array | 作息方案 | 方案切换不得修改历史记录 |
| `baseline_events` | JSON array | 原始习惯事件 | 只在用户明确重置时删除 |
| `task_events`（6.5 新增） | JSON array | 任务生命周期事件 | `TaskEventCodec`；未知类型/损坏条目解码时丢弃；上限 1000 条，追加式，删除任务不删事件 |
| `task_history_migrated_v65_0`（6.5 新增） | Boolean | 6.5 存量迁移是否已执行 | 幂等标记；迁移只补可可靠推断的事件 |

## `goals` 字段

必须字段：`id`, `title`, `weeklyTarget`, `durationMinutes`。

向后兼容字段及默认值：

| 字段 | 默认值 |
|---|---|
| `metricType` | `时长` |
| `metricTarget` | 空字符串 |
| `minimumVersion` | 空字符串 |
| `resourceTitle` | 空字符串 |
| `resourceUnit` | 空字符串 |
| `completedThisWeek` | `0` |
| `minimumCompletionsThisWeek` | `0` |
| `completionWeekKey` | 当前周 key |
| `desiredOutcome` | 空字符串 |
| `firstAction`（6.2 新增） | 空字符串 |

6.2 的“第一步动作”只新增可选字段；旧 `resourceTitle` 和 `resourceUnit` 继续完整读取与写回。

## `task_events` 字段（6.5 新增）

每条事件对象：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `id` | 新生成 | 事件自身 ID（`newItemId`） |
| `itemId` | `0` | 关联任务 ID；删除任务后仍保留 |
| `type` | — | 枚举 storageKey：`task_created` / `task_scheduled` / `task_rescheduled` / `task_completed` / `task_uncompleted` / `task_to_inbox` / `task_deleted` / `task_restored` |
| `recordedAt` | — | 事件发生时刻 (ms)；`<=0` 与未知 `type` 的条目解码时丢弃 |
| `title` | 空 | 事件发生时的任务标题 |
| `scheduledAt` | `0` | 安排/改期目标时刻；`0` 表示无；完成率分母按它归日 |
| `extra` | 空 | 细节（完成等级"完成/最低版本"、原因等） |

兼容约束：读取一律 `opt*`；未知字段不回写；未来版本可安全删除 `task_uncompleted` 占位——当前无触发 UI。

## `resources` 字段

必须字段：`id`, `title`。

可选字段：`url`（默认空）、`selected`（默认 `false`）、`summary`（默认空）。

6.2 中 `selected` 只表示资料库“常用标记”，不再表示新目标必须继承的全局标准。删除资料时不得同步删除目标；目标保留已有文字依据。

## 回归测试范围

- 旧目标缺少后加字段时可读取。
- 当前目标编码后再解码字段完全一致。
- 旧资料缺少 `selected` / `summary` 时可读取。
- 损坏的目标或资料 JSON 返回空列表且不崩溃。
- 后续每新增一个持久化字段，至少增加一个旧数据缺字段测试。
