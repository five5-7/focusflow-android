# FocusFlow 9.0 候选手动验收

用途：维护者在当前 OPPO / ColorOS 17 / Android 17 上准备正式发布前的手动检查。版本与安装包以本轮审计报告最终记录为准。安装稳定签名 Release 包并覆盖已有应用，保留数据；本清单不需要 dsh、ADB 或额外自动化。

## 先核对数据与日常闭环

1. 安装前记下现有待办、计划、课程和最近历史，覆盖安装后检查记录、已开启的提醒和外观设置仍在。到版本路线图核对候选号和构建号。
2. 用底部＋记录一件事，安排到数分钟后，回到桌面等提醒；通过通知或应用完成/改期，再回到今日页核对状态和历史。补做一次删除、撤回/回收站恢复，确认内容与关联没有丢失。
3. 打开一条重复待办，检查完成、跳过、暂停或停止的现有操作，以及次日/下次实例的状态；不期待系统自动替未处理任务顺延。
4. 选择已经明确归为同一门课的多个课次，检查课程分组；从最近任务移走应用后重新打开再看。需要进一步确认进程重建时，可在系统应用信息中停止应用后手动重开；记录实际操作。只同名但未归组的课次不算分组缺陷。

## 核对本轮改期与通知修复

5. 为今天和明天准备没有合适空档的安排，再打开一条高/中优先级错过事项的调整建议：应提供“保留并重新安排”，点击进入手动选择，不应直接排到冲突的明天 09:00。明天有空档时仍能使用具体改期建议。
6. 开启快速记录通知，确认通知入口能打开应用。暂时关闭系统通知权限后回到应用：不应闪退；恢复权限并再次回到应用，通知应重新尝试出现。最后关闭应用内快速记录开关，重开应用后确认通知不再续启。测试后恢复原设置。
7. 检查通知总开关、渠道、免打扰和一次性静音的正常行为。保留一项未来提醒，真实重启手机后观察恢复；若系统未自动启动应用，手动打开一次再核对，记录两者区别。
8. 到设置检查更新：显示当前安装版本与可用发布版本，不能把旧正式版写成当前版本或执行降级。rc→rc 和乱序 Release 的逻辑已有自动测试；远端没有相应候选 Release 时，不把手动检查未出现更新记作失败，也不为了测试创建 Release。

## 核对最近 UI 修订

9. 默认字号与系统大字号下，检查所有主/副页及设置分区问号与标题右侧位置、可点击范围和帮助主题。截图中的页面只是示例，滚动检查其余入口。
10. 日、周、课表模式：图例与 06:00/24:00 等刻度不能遮挡；“今天/未来7天/固定课表”与模式按钮处于同一行右侧；提醒副页的导航标签应为短名“提醒”。
11. 展开今日状态卡检查四角按压反馈、内嵌按钮和开关不会误触收起。快速点击跳转类卡片，观察反馈、连续点击和返回是否自然、没有重复跳转。
12. 图片背景＋亚克力/毛玻璃下比较冷启动首开、首次展开与再次展开；观察背景闪帧、卡顿和悬浮底栏。快速记录弹出/关闭键盘后，底栏和弹窗操作应可见；关闭动画时再走一次主要路径。

## 一天正常使用与结果记录

完成上述针对性检查后，按平常方式使用一天，覆盖前后台切换、跨日、实际提醒和重复实例。记录崩溃/ANR、提醒漏发或重复、数据变化及可复现步骤。25 分钟压缩切换记录不能代替这项检查；视觉通过也不等于量化帧率改善。
