# FocusFlow 8.3.0 实施检查点

基线：`8.2.2-rc.4` / versionCode 538，远端提交 `c7b4e53`，Run 383 的单测、Debug/Release、签名和版本元数据检查均通过。

本文件用于支持随时中断与恢复。每个检查点独立提交；完成前不合并、不发布，也不把 CI 成功称为正式版。

## 冻结范围

1. 把通知、通知渠道、横幅说明、精确闹钟、电池优化和厂商自启动指引汇总到一个权限中心。
2. 逐步替换不可靠的课表截图识别；先修结果可读性并抽出导入来源，待确认浙江大学实际课表来源后接入网页数据。
3. 修复安装或升级后的前几次启动中，页面切换、展开收起等动画普遍掉帧的问题。

## 检查点 A：权限中心

### Android 可以读取

- 应用通知总开关；
- FocusFlow 任务提醒、饭点提醒两个通知渠道的重要性；
- 精确闹钟能力；
- 是否忽略 Android 电池优化。

### Android 无法可靠读取

- ColorOS 的横幅／悬浮通知独立开关；
- ColorOS 的允许自启动、关联启动和厂商后台策略。

这些项目必须标为“需手动确认”，不能显示成已检测开启。应用提供 OPPO / realme / OnePlus 路径和一分钟后台实测，用实际送达结果辅助判断。

### 页面结构

- 今日页只保留简短“权限与提醒”入口；
- 详情页分为“提醒所需”和“体验增强”；
- 每项显示：状态、用途、检测限制和系统设置入口；
- 用户确认不再在今日提示后，只在设置页“检查更新”上方保留入口。

## 检查点 B：课表导入

当前入口把截图压缩后发送给视觉模型，再解析模型生成的 JSON。主要问题是模型可能漏课、误拆课程和教室，并且需要 API key。课表网格为了容纳一周课程使用 `TextOverflow.Ellipsis`，识别后的待确认卡本身没有主动截断。

8.3 先完成：

- 导入来源抽象为统一的课程列表，保留去重、冲突、编辑和逐项确认；
- 待确认结果优先完整显示课程名、节次与地点；课表网格点开课程可看完整内容；
- 保留手动录入作为无网络兜底；
- 在没有确认真实数据源前，不猜测教务接口、不保存账号密码、不绕过登录或验证码。

rc.7 将 rc.6 的完整 WebView 手动导航替换为原生短路径：入口为“从教务网导入 → 浙江大学”，用户只在应用内输入账号密码，客户端动态读取 CAS 表单与当前公钥、加密密码、建立仅驻留内存的 Cookie 会话，再读取页面实际选中的学年／学期并请求学生课表；界面显示连接、加密、认证、读取学期、获取课表和解析进度。账号、密码与 Cookie 不持久化、不写日志，密码字段提交后立即清空，流程结束擦除字符数组，不绕过验证码或账号解锁。新课进入待确认；只有课程名、星期与节次可唯一匹配（或同日仅有唯一同名课）时才更新已有课程，并保留 ID、确认／启停状态和生效期；歧义项新增候选，本地缺项不删除。仍需维护者账号真机验证实际响应、验证码／锁定异常分支及单双周行为。


rc.8 根据 OPPO 真机反馈修复认证阶段超时：同一网络下系统浏览器可打开 CAS，但 rc.7 会把登录 POST、跨域跳转和最终教务页面正文合并等待，任一环节超过 18 秒都显示为“验证账号超时”。现将认证提交与教务会话建立拆成两个进度阶段，补齐浏览器导航请求头；到达 zdbk 并接收 Cookie 后跳过无用正文，认证段单独使用 35 秒响应上限。超时信息按阶段区分，密码 POST 不自动重试，避免重复认证触发风控。


rc.9 将浙江大学导入 Activity 从原生 `LinearLayout/EditText/Button/ProgressBar` 迁移为 Compose：读取用户现有主题与深色模式，使用卡片化账号区、独立隐私说明、密码显隐、键盘完成操作、全宽主按钮和七段状态进度。失败时当前步骤标红并显示原因，保留账号但密码仍在提交时清空；页面支持安全区、键盘避让、滚动、窄屏和大字体。登录客户端、数据解析和同步规则不变。

rc.10 针对维护者确认的“图片背景 + 亚克力”复现路径继续检查点 C：背景图在 `setContent` 前于 IO 线程解码并作为首屏初值复用，避免首屏后第二次整页重绘和玻璃层重建；隐藏页签预热由固定延时连续三页改为触摸可取消、每个空闲窗口一页；提醒恢复与活动会话轮询不再在主线程读取偏好。画质、亚克力参数和用户外观设置不降级。

## 检查点 C：首次动画性能

已确认的高风险路径：

- `FocusFlowApp` 首次组合在主线程同步读取大量 SharedPreferences 和 JSON；
- `ON_START` 紧接着重复读取任务、活动与历史；
- 首帧后连续三帧组合其余三个完整页签，可能与用户立即操作竞争；
- 首次进入不同页面时仍会触发 Compose/JIT 的惰性初始化。

实施顺序：

1. 建立启动快照，在后台线程一次读取初始数据，界面就绪前不启动页面动画；
2. 去掉首次 `ON_START` 对刚读取数据的重复加载；
3. 把隐藏页签预热安排到首屏稳定以后，并在用户开始交互时让路；
4. 为启动、首次切页、首次展开和重复展开分别记录帧耗时，不能只凭动画时长判断；
5. 最终使用 OPPO Find X8 Ultra / ColorOS 16 / Android 15 的稳定签名 Release 包验收。

rc.5 已接入原生 `FrameMetrics` 记录：Logcat 标签为 `FocusFlowFrames`，分别输出启动首帧窗口、首次／重复切页、首次／重复展开的帧数、平均值、P90、最大值和超预算帧数；同时记录启动快照耗时。真机可用 `adb logcat -s FocusFlowFrames:I` 采集。

## 版本与完成标准

- 第一份可安装候选按维护者要求承接既有 RC 序号：`8.3.0-rc.5` / versionCode 539，不重置为 rc.1；WebView 浙大教务候选为 rc.6；原生自动登录与同步候选为 rc.7；认证超时修复候选为 rc.8；Compose 导入 UI 候选为 rc.9；图片背景＋亚克力首次动画候选为 `8.3.0-rc.10` / versionCode 544，rc.5 至 rc.9 已废弃；
- 权限中心不得把 ColorOS 私有开关伪装成可检测状态；
- 浙大教务接入只宣称已完成代码、解析与同步规则的自动测试；实际账号登录、页面字段、验证码／锁定异常路径与单双周行为在真机验收前不得宣称完成；
- CI 需通过完整单测、Debug/Release 构建、稳定签名和版本元数据检查；
- 真机需验证冷启动、前三次页面切换、展开收起、通知横幅、后台一分钟测试和重启恢复。
