# FocusFlow 8.0 正式版发布审计

状态：候选修复中。本文定义发布范围与门槛；不合并 PR、不建立 Release。

## 已核对的基础

- 代码基线：7.9 至 7.12 的改动连续叠加在 PR #42；当前正在准备 `8.0.0-rc.2` / versionCode 509。
- 自动证据：Run 297 和 8.0 rc.1 的 Run 298 均通过版本元数据、单元测试、Debug/Release 构建、稳定签名和 APK 元数据校验；rc.2 待独立验证。
- 当前正式 Release 仍是 7.1.3。任何候选或 CI 成功都不能改写这一事实。
- 7.4、7.9 至 7.12 的历史候选说明不能各自被单独发布；8.0 必须以最终整合候选为唯一来源。

## 8.0 可收束的已实现内容

1. 日常使用与提醒：7.2 至 7.4 的保守提醒、精力采样、活动生命周期和后台诊断。
2. 收集箱与计划：7.5 的待整理／推进／参考流转，任务恢复与历史记录。
3. 课程与通勤：固定课表、节次表、地点、课程生效期、启停、单删/批删和通勤档位。
4. 校园生活边界：首次选择、关闭后不删数据、入口提示、当前位置空状态、电动车电量。
5. 视觉与数据治理：统一设计语言、顶部今日状态、收集箱筛选、空挡分类与图、历史删除与统计重算。

## 发布前必须完成

- 真机覆盖安装 rc.2：确认课程生效期、已确认课程批量删除、历史单删/批删/清空后的统计、课程不会被误删。
- 复现测试：安排与课程冲突的活动，确认进入计划不闪退；测试重叠课程和“通勤时长 > 课间”，确认显示 0 可用空挡且可安全删课程。
- 验证空挡：无课日、单门晚课、两门课间通勤、已有日程切分、关闭校园生活五种情况。
- 验证日常闭环：收集箱记录 → 安排 → 锁屏/后台提醒 → 完成/改期 → 历史与统计。
- OPPO / ColorOS 16：通知权限、后台限制、自启动、锁屏到点与重启后恢复；一分钟测试仅作诊断，不替代真实到点。
- 视觉：浅/深色、内置与自定义主题、窄屏、大字体、手势/三键导航；重点检查今日状态、课程卡片、空挡图和历史危险操作。
- 发布整理：将路线图中 7.9–7.12 的候选历史收束为“8.0 已实现”，保留历史记录但不在日常路线图逐项冒充当前候选；同步 README、CHANGELOG、说明书、快速入门和版本规则。

## 必须修正的文档冲突

- `VERSIONING.md` 同时保留 7.2、7.4 和 7.12 的“当前”叙述；8.0 前必须改成单一当前候选。
- `docs/7.11-course-gaps-commute-plan.md`、`docs/7.12-data-history-ui-plan.md`、`docs/gap-chart-redesign.md` 的构建状态需更新为 Run 297 的真实结果，并仅保留真机验收待办。
- 应用内路线图不应继续把 7.9–7.12 全部展示为平行候选；需要以 8.0 摘要替代。

## 不纳入 8.0

- 单次安排时覆盖通勤耗时。
- 真正仅当天有效的交通方式／电动车状态。
- 新的地图 SDK、云同步、桌面小组件、通用表格识别。

这些是后续独立功能，不能为了“凑正式版”改变已经通过构建的排程和数据边界。

## 8.0 候选流程

1. 完成上述真机验收，记录每项结果和复现条件。
2. 仅修复验收中确认的问题；每次候选递增 `rc.N` 与 versionCode。
3. 冻结内容，执行最终完整 CI。
4. 将正式版本名改为 `8.0.0`，再次递增 versionCode，执行最终 CI。
5. 经维护者明确确认后合并、打 tag、建立 GitHub Release。
