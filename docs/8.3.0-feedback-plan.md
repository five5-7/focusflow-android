# FocusFlow 8.3.0 用户反馈初步处理

记录日期：2026-09-20。基线为 `8.3.0-rc.10` / `876abca`。

这份清单保存真机使用中发现的问题。先修复边界清楚、不会改变数据含义的缺陷；涉及数据结构和核心工作流的项目先完成交互与迁移设计。

## 第一批：直接修复

1. **收集箱长文本改变卡片宽度**：收集箱、逐步推进、参考三类卡片统一占满可用宽度，文本只在卡片内换行。
2. **上一步／下一步位置**：在现有位置基础上继续向左右两侧各移动 2dp。
3. **加号弹窗被历史导航收起后无法重开**：每次点击加号生成新的弹窗请求序号，强制重新注册页内弹窗。
4. **课程编辑弹窗异常空白**：移除正文内的第二层纵向滚动；地点改用自适应换行，不再固定每行三项。
5. **弹窗按钮被挤压**：统一弹窗按钮区允许换行，适配窄屏与大字体。

## 第二批：产品与数据设计

### 课程和日程

- **同一课程的多个上课时间**：把“课程资料”和“上课时段”拆开。一个课程保留名称、通知和启停状态，下面可有多个星期／节次／地点；旧数据迁移时按课程名归组，仍保留每条原始时段。必须避免仅凭同名错误合并不同课程。
- **课程通知**：设计全局课程通知开关，并允许单门课程覆盖；默认提前时间复用现有提醒设置。通知身份按“课程 + 具体时段 + 日期”生成，避免同课多时段互相覆盖。
- **今日改期**：允许活动开始前、进行中和结束后修改，并提供同批活动的批量移动日期入口。
- **日视图显示今明两天**：先调整为可切换的“今天／今明两天”，确认纵向密度后再决定默认值。

### 待办、收集箱和加号

- **独立待办功能**：以现有 `Item` 为兼容基础，新增任务列表、详情、完成状态和可选截止日期；具体字段与入口另行讨论。
- **收集箱分类**：现有“待整理／逐步推进／参考”不再要求先进入收集箱再切分类；首页直接呈现待处理内容，低频分类改成筛选或标签。
- **加号菜单**：将“快速记录”保留为首项，增加“待办”和“计划”；“安排空闲活动”降低层级。
- **弹性安排入口**：在日程与待办详情同时提供可见入口，并用首次提示说明它是时间范围，不是具体开始时间。

### 通知和误删恢复

- **自定义通知**：用户可填写通知文本，并从“完成／稍后／移入收集箱”中选择动作；动作必须复用应用现有任务变更逻辑。
- **撤回与恢复**：先为内容、收集箱项、待办和日程使用 Snackbar 撤回；再设计本地回收站与保留期限。历史统计记录不随恢复被重复写入。

### 长期与模糊活动

- 为“复习”等长期活动增加轻量模板：先收集范围、下一次可执行动作和复查日期；允许多个下一步排队，不要求首次就填写完整目标指标。

## 现有逻辑说明

### 收集箱、开始活动、安排时间

- **收集箱**保存“我想到了一件事，但还没决定什么时候做”。
- **安排时间**把这件事变成日程任务，并进入到点提醒、改期和完成流程。
- **开始活动**记录“我现在已经开始做什么”，包含预计结束时间和结束后的下一步。它可以临时开始，不要求先建立收集箱项。

当前问题是三个入口都在处理“要做的事”，界面却按数据状态拆成了不同操作，用户需要先理解内部模型。后续应在事项详情里统一提供“现在开始／安排时间／保留在收集箱”，由用户选择意图。

### 目标、下一步、逐步推进

- **目标**是长期结果和每周节奏，例如“完成高数复习”。
- **逐步推进**是还不能直接安排、需要拆解的方向。
- **下一步**是当前最小的可执行动作；现在系统只允许一个未完成的下一步，防止重复生成任务。

限制为一个下一步对并行推进不合适，也让操作显得绕。后续改成“下一步队列”：可添加多项、指定其中一项为当前行动，其余保留候选；简单事项无需先创建完整目标。

## 尚待复现

- 除课程编辑弹窗外，曾出现过另一处按钮挤压。第一批先用统一按钮换行覆盖常见原因；若仍出现，记录弹窗标题、字体大小和操作路径后再定点修复。
