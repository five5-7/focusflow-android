### 计划成员边界

计划删除默认只移除计划；可选择一并删除本计划的普通任务。重复实例与带父子捕获关系的条目不作为可选删除成员，继续由其原闭合路径管理；它们未被删除时的绑定仍纳入计划快照。所选墓碑在普通回收 UI 中隐藏，避免跳过计划闭包单独恢复；清除闭包时同步核销其普通回收组成员。零任务计划合法。

### 课程属性

恢复完整真实 Course 字段，包括课次／父 ID、星期、节次、学期、启用／确认状态、有效日期、地点及已存的外部身份线索。当前 Course 没有独立颜色字段，课程显示颜色仍由既有主题规则生成；不制造不存在的“颜色快照”。同名课程不被自动归并。

## 持久化

- 普通 TrashJournal 仍只读写 ordinary_items，原校验和迁移保持独立。
- 新的严格 `stage7_records_v1` Legacy 键保存 repeat_rule_closure、plan_binding_closure、task_batch_inverse、course_merge_inverse 和 course_split_inverse。课程删除组仍保存于 `course_recovery_groups_v1`。
- CoreDataSnapshot 统一投影两种键；核心变更、事件、计划、课程、普通回收组及新恢复记录通过一次 SharedPreferences commit 写入，使用既有 taskHistoryLock 和全快照 CAS。
- Room 复用 v7 已有 operation_records 表，版本和 schema 不变；同一事务写核心数据与完整负载。course_recovery 类型承载完整课程组，不扩展普通 TrashGroup。Legacy 导入同时导入两种恢复键，指纹纳入原文；未知版本、损坏负载、重复身份不当空集合处理，禁止替换原文。
- 影子对账包含完整 operation_records 内容，按操作 ID 比较；表的查询排序不被误当成业务顺序。
- 普通编辑不会因为某个旧恢复组失去动态资格而被阻止；动态冲突只在恢复／撤回入口判定。结构损坏仍拒绝覆盖。

## 中断、失败与通知

1. SharedPreferences commit 返回 false／抛异常不能靠读回内存宣称落盘。Stage7CommitGuard 阻止后续恢复副作用，要求真实进程重启重新读取；新建 store 对象不解除。课程原有三态 commit 与不确定守卫保留。
2. Course RESTORING 和课程逆操作 restoring 保存已提交的核心检查点。失败保持待续办；即使过了原窗口也不能清除。启动及课程闹钟恢复入口尝试全部待续办记录，失败时不宣称完成。
3. 课程逆操作回填仅接受完整“操作后偏好”或完整“已回填偏好”；未知后续编辑保留并暂停续办。水位允许更新但绝不倒退；等值／较新水位也执行一次明确的确认提交。
4. 课程广播读取发生次、写送达水位和发通知与课程删除共用互斥边界。删除／合并拆分逆转取消旧闹钟和已有课程通知；待续办的课次不发送用旧偏好的通知。恢复只排未来触发点，不补发过去通知。
5. 偏好回收只清除规范且无任何现存课程、恢复组或课程逆操作引用的键；损坏负载／未完成合并拆分／不确定提交时暂停。中断后可重新推导孤立键，逐文件确认，不能删除其它课次的偏好。
6. Room 单事务异常回滚；测试通过 SQLite 触发器拒绝恢复记录 INSERT，验证任务、计划、事件、组均不留下半写入。

## 清理与旧数据

- 清除恢复／撤回负载不删除历史，不清除已恢复活数据；重复规则只删除完整匹配的模板墓碑，受影响实例历史保留。
- 计划闭包清理只删完整匹配的所选墓碑；用户改过的对象保留。普通已恢复组的过期负载也可清扫。
- 更早的可读墓碑仍有旧数据入口，不补造不存在的闭合成员或时刻；没有可靠组时不自动清扫。旧重复实例维持原保护规则，不能从一条旧墓碑推断整条重复规则的永久清除。
- 清空对可清除部分按域提交；任何域失败即停止并提示未全部完成，后续重试不会影响已恢复数据；不是跨偏好文件的虚构全局事务。
