# 阶段 6 组①：多课次候选的只读内存预览（设计与授权边界）

日期：2026-09-28。基线：`handoff/stage6-local` @ `3b2f5d7`（已推送远端同名分支）。
上游依据：`9.0-stage6-course-identity-design.md`（设计审定）、`9.0-stage6-course-identity-review3.md`（第三次审定）。

## 1. 本件回答什么、不回答什么

`review3` 的判定是：`xkkh` **只被允许**作为"同一请求学年＋学期内的候选分组键"进入只读设计与内存预览；自动更新、合并与迁移**暂不放行**。

因此本轮交付的是一块**纯函数、只读、仅内存**的候选分组预览：

| 做 | 不做 |
| --- | --- |
| 把一批 `kbList` 候选行按 `(schoolYearCode, termCode, xkkh)` 分组 | 不写任何存储、不落库、不生成父记录 |
| 标出"看起来同班多课次"的候选组 | 不做归并、不改 `Course.id` |
| 标出**必须先人工核对**的组与原因 | 不动提醒键、`CourseLocationOverrides`、PendingIntent、通知标签 |
| 保持与原始响应行序号的可溯源关系 | 不改 Room schema、不打开 Room 激活、不改版本号 |

组件位置：`app/src/main/java/com/sakata/focusflow/CourseIdentityPreview.kt`（`internal object`）。它**没有被任何写入路径调用**；当前只有单测消费它。

## 2. 分组规则

**分组键是完整三元组** `(schoolYearCode, termCode, xkkh)`——同号跨学期永不相遇，这是 `review3` 明确要求的限定。

| 情形 | 结果 |
| --- | --- |
| 缺学年/学期代码 | 该行独立成群，`NEEDS_REVIEW` + `MISSING_REQUEST_CODES` |
| 候选键为空 | 该行独立成群，`NEEDS_REVIEW` + `MISSING_SELECTION_KEY` |
| 该行标题为空 | 该行独立成群，`NEEDS_REVIEW` + `MISSING_TITLE` |
| 同键、同标题、多行、课次互不相同 | `MULTI_MEETING_CANDIDATE`（**候选**，仍不可归并） |
| 同键只有一行 | `SINGLE_ROW` |
| 同键但标题不一致 | `NEEDS_REVIEW` + `CONFLICTING_TITLES` |
| 组内有**任何**行标题为空 | `NEEDS_REVIEW` + `MISSING_TITLE`（空标题**不等于**"标题一致"） |
| 组内有缺星期/节次的行 | `NEEDS_REVIEW` + `INCOMPLETE_ROW` |
| 组内出现完全相同的星期＋节次 | `NEEDS_REVIEW` + `DUPLICATE_MEETING`（不得当成多课次） |

**优先级**：`reviewReasons` 非空 ⇒ 状态必为 `NEEDS_REVIEW`，**优先于** `SINGLE_ROW`。即"只有一行但证据不足"是待核对，而不是干净的结论；取值方向一律 fail-safe。

**原因记录**：同一行/同一组命中多个原因时**全部记录**（不吞）。顺序固定为 `INCOMPLETE_ROW` → `MISSING_TITLE` → `CONFLICTING_TITLES` → `DUPLICATE_MEETING`（独立成群的行按 `MISSING_REQUEST_CODES` → `MISSING_SELECTION_KEY` → `MISSING_TITLE`）。

输出按组内首行序号稳定排序，输入顺序不影响结果。

`PreviewGroup.previewKey` 只是**展示/日志用**的组合串：它**不是持久身份**、**也不保证唯一**（字段未转义，缺代码的行会得到 `//KEY` 这类串），不得用作列表键或 Map 键；需要唯一键时用 `rows.first().sourceRowIndex`。

## 2.1 已知限制（复验提出、当前有意保留）

- **键与代码不 trim**：分组键用原始字符串比较，而标题比较是 `trim()` 后比较。解析器路径不可达（`firstText` 已 trim），只有手工构造输入时可能"静默分裂成两组且无 review reason"。保留现状、在此登记。
- **2026-09-29 修正**：同星期节次部分重叠现在标记 `OVERLAPPING_MEETINGS` 并待核对；完全相同仍标记 `DUPLICATE_MEETING`。这仍不证明教学班身份，预览不会触发写入。


## 3. 解析器的配套改动（最小）

`ZjuTimetableCandidateRow` 增加 `title`（课程标题原文，默认空）。原因是"同号异标题必须待核对"这条规则需要它；`title` 不参与任何身份判定，也不写入持久层。

`ZjuTimetableParser` 里把 `title` 的计算提到候选行构造之前，行序号与过滤行为**不变**（候选行本来就在合法性校验之前登记，非法行仍然进候选）。
