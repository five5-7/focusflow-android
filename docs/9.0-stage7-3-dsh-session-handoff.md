## 2. dsh 并行方式

- 主会话是唯一业务代码写者。最多委派两个**只读**子智能体：一位找 Legacy/Room 事务、损坏组与旧数据反例；另一位找 UI 删除/恢复入口、通知及时间边界。子智能体交回具体文件、可证伪输入和预期；不得编辑文件或运行会改仓库状态的命令。若 dsh 当前配置没有子智能体工具，主会话顺序做这两项，不假装已运行。
- 长时间单测/构建可用 dsh 自身的后台任务工具，记录任务 ID 和最终退出码，不能只看“已启动”。`bg_start` 和 `review_stage` 是此项目 **OpenCode 插件**，不要在 dsh 中假设存在。后台跑 Gradle 时不要在同一 worktree 并发启动另一轮 Gradle 构建。
- 会话 B 只写自己的 7.4 设计文档，在另一个 worktree；A 不改 B 的文件，也不依赖 B 尚未交付的结论。A 达到可审查的小提交后，把 diff/提交号交给不同模型做只读复核。
