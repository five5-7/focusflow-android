# V2 活动模式实现边界

## 状态机

| 当前状态 | 事件 | 下一状态 | 数据动作 |
|---|---|---|---|
| `active` | 用户延长 | `extended` | 更新预计结束、延长次数与原因 |
| `active` / `extended` | 到点 | `awaiting_confirmation` | 保留活动，不自动判定失败 |
| 任一开放状态 | 结束 | `completed` | 写入实际结束时间与结束选择 |
| 任一开放状态 | 放回收集箱 | `skipped` | 写入实际结束并生成重新安排项目 |
| 任一开放状态 | 开始下一步 | `completed` + 新 `active` | 结束当前活动并建立下一活动 |

开放状态仅包括 `active`、`extended`、`awaiting_confirmation`。应用恢复时只恢复最新的开放活动。

## 组件职责

- `ActivityMode.kt`：活动会话、提醒设置和冲突摘要的数据结构；不依赖 Compose 或 Android 服务。
- `PrototypeStore.kt`：兼容旧记录的 JSON 迁移、会话状态变更、延长限制与设置持久化。
- `MainActivity.kt`：开始表单、今日运行卡、转场对话框、活动历史与设置界面。
- `ReminderScheduler.kt`：预告和到点闹钟；有精确提醒权限时使用精确闹钟，否则安全回退。
- `ReminderReceiver.kt`：展示通知并处理通知中的结束、延长操作；不直接修改任务日程。
- `BootReceiver.kt`：应用更新或手机重启后恢复最新开放活动的提醒。

## 不可静默执行的动作

- 延长与固定任务或课程冲突时，只显示影响，不移动或缩短原日程。
- 到点未回应时只进入待确认，不写入“失败”或猜测实际结束时间。
- 关闭通知时只取消闹钟，不删除活动记录。
- 娱乐、游戏和休息使用同一套记录结构，不附加负面分数。

## 兼容与恢复

- 1.6 旧活动记录只有 `id`、`name`、`endsAt`、`status`；加载时用 `id` 作为旧记录的开始时间，并补齐其他默认字段。
- 所有提醒 request code 由 session id 稳定生成，延长前会取消旧预告与到点闹钟。
- 手机重启时：未到点则重设闹钟；已到点则标记待确认，并在允许通知时立即给出转场提醒。
- 通知动作修改存储后，运行中的 Compose 页面每秒同步最新开放活动，避免显示过期状态。

## 发布边界

- `main` 和 `archive/focusflow-1.6` 保持 1.6 稳定基线。
- V2 只在 `v2/activity-mode` 开发；预览构建名为 `FocusFlow-v2-preview-apk`。
- 真机验证完成前不把 V2 分支快进到 `main`。
