## 二、被删除的材质，以及**判定性判据**

「毛玻璃」与「亚克力」都做了多版，最终由维护者删掉。**留档是为了别再加回来。**

试过的做法：① 单纯调低不透明度；② 材质层加 `Modifier.blur`；
③ 把页面底色用同一套渲染画进卡片 + 40dp 模糊。

**三版都被判定为"不透明平面卡片"。判定性判据（务必记住）：**

> 卡片 `#c1e0e4` 比它所覆盖的页面底色 `#e9eced` **更饱和**。
> 半透明只能把面板**往背景方向拉**，不可能比背景**更饱和**。
> 所以它根本没透。

**为什么我先前误判成"通过"**：我量"边缘能量"（相邻像素平均绝对差），
卡片内 2.29、页面 66.09，就宣布"低 7~28 倍 = 糊过了"。
但这个指标**区分不了两件相反的事**：

- 卡片里是**糊过的图** → 平坦
- 卡片**压根不透明、就是一块平色** → 也平坦

**教训：验证指标必须能区分"做到"与"没做"。**
如果一个数在"成功"和"完全失败"两种情况下都长一样，它就不是证据。

## 三、设备操作铁律（血教训：我弄丢过维护者的数据）

### 1. 任何对 `focusflow.xml` 的写操作，**先备份**
用户的全部数据（条目、课程、主题预设、自定义配色）都在
`/data/data/<pkg>/shared_prefs/focusflow.xml` 这**一个文件**里。

**可用的备份方式**（`adb shell cp` 到 `/data/local/tmp` 会**权限拒绝**，app 身份写不了那里）：

```powershell
cmd /c "`"$adb`" -s $SERIAL exec-out run-as com.sakata.focusflow cat /data/data/com.sakata.focusflow/shared_prefs/focusflow.xml > D:\focusflow\.tmp\prefs-BACKUP-<stamp>.xml"
```

**2026-09-11 的事故**：我用 `sed -i` 直接改这个文件**四十多次、一次备份都没做**，
文件从 50,049 字节变成 1,641 字节，用户数据全丢。
**这不是"运气不好"，是流程错误。** 别重复。

### 2. 改偏好用"捕获组 + `.` 代替引号"
Windows 参数引号会吃掉双引号，`sed` 里直接写 `"` 会失败；而用 `>value<` 匹配
又会误伤**同值的其它键**（`>gradient<` 同时命中页面背景与课表底色，已踩过）。
正解：

```powershell
# 只命中 card_material，且不含任何字面双引号
sed -i 's|\(card_material.\)>[a-z]*<|\1>soft<|' <prefs>
# 布尔值同理： s|\(dark_mode. value=.\)false|\1true|
```

### 3. 其它已知坑
- `uiautomator dump` 会冻结 UI 2–5 秒并**吞掉紧随其后的点击** —— 每次点击后重新 dump 校验。
- `pwsh` 包装层在长命令（构建 + adb 连跑）上**经常超时**，
  改用后台任务 + `job_output` 轮询；构建结果以日志里的 `BUILD SUCCESSFUL` 为准，
  **不要**因为包装层超时就以为构建失败。
- 装机后务必核对 `dumpsys package <pkg> | grep lastUpdateTime` ——
  包装层超时会让"装了没有"变得不确定（维护者就问过"你确定安装了？"）。
- `.tmp` 下的 PowerShell 脚本必须 ASCII-only，否则 PS 5.1 会乱码。
- `$PID` 在 PowerShell 里是**只读**的，别拿它当循环变量。

## 四、性能排查：已经证伪的路，别再走

`docs/8.2.0-checklist.md` §六第 12 条有六次实验的完整数据。结论：

1. **150ms 是"首次切换页签"的固有代价**，与目标页无关
   （今日→日程 / →计划 / →设置 三者完全一样），首次光栅化整屏那一层所致。
   重帧率 3.0–3.5%，**在预算内，不是缺陷，不要动它**。
2. 两条优化路线**已被实验证伪**，不要再试：
   - 把设置页换成 `LazyColumn`（"设置页太长"是错的）；
   - 优化外观页的组合量（`remember` 与渐进组合两次都毫无效果 ——
     因为 200ms 那一帧是**首次组合**，且大头根本不在这页）。
3. 「打开设置→外观」是唯一超预算的（p99 200ms、p90 36–40ms），
   且**是这一页独有的**（其它子页都落在 150ms 基线）。
   判据用 **p99 与 p90**，不要用单次重帧率 —— 它在轮次间波动 5.17%~9.26%。
4. **文本解析 atrace 这条路走不通**（显示管线的 B/E 标记不按栈嵌套，
   会算出 9 秒 trace 里 8372ms 的切片）。要看切片必须上 Perfetto UI 或 `trace_processor`。

## 五、交付与发版

- 本地 release 包**是 debug 证书签的**（四个 `FOCUSFLOW_SIGNING_*` 环境变量没设）。
  要分发／装机测试的应是 **CI 出的稳定签名产物**（见 `docs/signing-policy.md`）。
- 上传分支（凭据缺失时 `schannel` 会报 `SEC_E_NO_CREDENTIALS`，
  换 TLS 后端可绕开）：

```powershell
git -c http.sslBackend=openssl -c credential.helper= push `
  "https://x-access-token:<TOKEN>@github.com/five5-7/focusflow-android.git" agent/focusflow-8.0.0
```

  （`gh auth login --with-token` 可能因 token 缺 `read:org` 作用域而失败，
  但普通 `git push` 只需要 repo 权限，仍可用。）
