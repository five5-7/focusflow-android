## 总原则

1. 先同步；旧 checkout、旧分支、dirty worktree 都不能出结论。
2. 不运行 "pm clear"、不卸载、不删除私有数据；安装只用 "adb install -r"。
3. 只装 Run 551 的稳定签名 APK；不装 debug 包绕过签名问题。
4. key、密码、Authorization、真实课表隐私图不进 log、截图或报告。
5. 每个用例只写三种状态：运行过并通过、运行过失败、未执行；设备型号不符另写“设备不满足目标矩阵”。
6. 失败停止当前链路，保存原始 XML/截图/dumpsys，不重试到偶然通过。

## P0：几分钟自动完成

### P0-A 同步、版本、签名、启动冒烟

先准备 Run 551 artifact FocusFlow-8.3.0-rc.28-run-551-apk，解压并记录绝对路径。仓库根目录执行：

§powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dsh-stage9-fast-acceptance.ps1 -Install -Apk <APK绝对路径>§

脚本会检查工作区无未提交改动、fetch 远端、切换到目标分支、仅 fast-forward 到 origin/stage9/regression-freeze，要求本地 HEAD 与远端一致，运行 git diff --check，检查 versionName/versionCode、gradlew 和凭据备份排除规则，校验证书 SHA-256，安装并启动应用，导出 UIAutomator XML、Activity 顶层、启动截图和通知 appops 状态。

预期：

- 输出“快速验收通过”；
- adb install -r 输出 Success；
- 证书 SHA-256 为 650a17f2bbc6d3cf7ac436e3ce7d4cbc1381cfd29052d6a8e06e70361ef48e8e；
- 顶层 Activity 属于 com.sakata.focusflow；
- UI XML 含“今日”“日程”“计划”“设置”；
- 证据目录有 git-status.txt、git-head.txt、device-properties.txt、apk-signing.txt、activity-top.txt、ui-launch.xml、launch.png、report.json。

脚本默认不跑 Gradle；如要顺手重跑 Debug 聚焦单测，再追加 -RunGradle。如果工作区有本地改动，脚本会停止而不是覆盖；此时另建干净 worktree，不要 reset。

### P0-B adb 设备基线

脚本已经保存：

§adb -s <serial> shell getprop ro.product.model§

当前目标设备是维护中的 OPPO 测试机；它已升级到 ColorOS 17 / Android 17，因此本机即为阶段 9 目标基线。记录升级后的系统版本。另有 ColorOS 16 / Android 15 设备时，再作为兼容性扩展验证，不阻塞本机验收。

### P0-C 四页导航

启动后，每次操作前执行：

§adb -s <serial> shell uiautomator dump /sdcard/dsh-ui.xml§
§adb -s <serial> pull /sdcard/dsh-ui.xml <证据目录>\\ui.xml§

在 XML 找 text 或 content-desc 为“今日”“日程”“计划”“设置”的节点，读取 bounds="[left,top][right,bottom]"，取中心点后执行：

§adb -s <serial> shell input tap X Y§

点击后等待 800 ms，再 dump XML 和截图。预期对应页签成为选中项，应用不闪退，底栏仍可见，页面没有被底栏整块盖住。保存 nav-today.*、nav-schedule.*、nav-plan.*、nav-settings.*。找不到可点击节点时写“自动化选择器缺失”，不要盲点坐标。

## P1：课表门禁（本轮最高优先级）

### P1-A 进入配置页

从“设置主页”点击“高级工具”，再点击“课表识别（视觉模型）”。

如果看到“校园生活关闭 · 点击查看开启方法”，这是前置开关阻塞，不是识别代码失败。只有本轮明确允许准备课表识别时，才按界面提示开启校园生活，再重新进入。

进入后应看到：

- “截图识别（可选联网）”
- “先保存配置，再点击能力测试。测试使用生成的小图片，可能产生 API 费用。”
- “能力测试”
- 能力测试运行中显示“取消请求”（静态配置页没有该控件）

无 key 时点击“能力测试”，预期“请先填写可读的 key”，不崩溃、不把服务列为可审核。

真实服务返回未通过严格结构化解析时，失败提示会附带脱敏响应摘要（字节数、截断 SHA-256、顶层键和候选形状），不记录 key、原始响应、课程名或图片。该摘要只用于区分“模型未遵守 schema”和“解析器形状不匹配”，不能把失败自动判为服务端或客户端责任。

### P1-B 完整能力服务

通过 dsh 私密输入填写 HTTPS 根地址、模型 ID 和 key，不把输入回显到 shell 或报告。保存后点击“能力测试”，预期连接、图像读取、结构化输出均通过；再点“设默认”，预期显示“已通过能力测试 · 默认”。

从“计划”主页课程区域选择“导入截图”，选择一张无隐私测试图。预期顺序：

1. 出现“正在识别课表”和“取消识别”；
2. 完成后出现“识别完成，请逐条确认、编辑或拒绝”；
3. 候选显示标题、星期/节次或“无法唯一定位”、warnings；
4. 关闭审核或点“取消”，显示“已取消审核，本次未导入”，课程数量、课程 ID、提醒完全不变。

### P1-C 部分能力服务（用户指出的门禁问题）

准备一个探针结果：connected=true、structured=true、image=false。需要第二家真实 HTTPS 视觉服务，或由服务端提供受控测试探针。Android targetSdk 35 的 release 包不信任用户 CA，因此本地 HTTP/自签名代理不能作为本项证据；若只能得到 structured=false，标记“未执行部分能力试用”，不能推断代码失败。

不要点“设默认”。预期必须全部成立：

- 服务出现在“选择截图上传服务”列表；
- 说明包含“仅用于手动逐条审核，不会自动导入，也不能设为默认”；
- 不能设为默认；
- 选择服务后仍进入审核预览，而不是被旧门禁拦截；
- 审核项有“确认”“编辑”“拒绝”；
- 没有点击“应用审核结果”前，课程数量、课程 ID、提醒不变；
- 替换模型、地址或 key 后，旧探针失效，必须重新测试。

### P1-D 取消和错误分类

分别测：

- 识别进行中点“取消识别”：立即结束进度，显示“已取消，本次未导入”，课程和提醒不变；
- 让服务延迟超过 120 秒：失败且不写入；
- 识别中修改模型/key 或删除服务：显示“已取消、超时或服务配置发生变化，本次未导入”；
- 返回 3xx、401/403、413、429、非法 JSON：只显示分类错误，不显示 key、完整响应或 Authorization。

取消后若课程仍被写入，立即停止 P1，保留 UI XML、截图、Activity/notification dump 和服务端请求摘要。

### P1-E 审核决策

准备至少三个候选：

1. A 点“确认”；
2. B 点“编辑”，只改课程名，不填星期/起始节/结束节，点“保存编辑”；预期仍待审核并提示审核信息不完整；
3. C 点“拒绝”；
4. 点“应用审核结果”。

预期：只有完整有效的 A 写入；B/C 不写入；重启后仍如此。无法唯一定位、重叠星期/节次的候选必须保留警告并人工检查，不能自动补星期/节次。

## P2：P1 完成后才做的短设备回归

### P2-A 通知/重启

设置未来 2–3 分钟提醒，记录通知权限和渠道。先测前后台切换：

§adb -s <serial> shell am force-stop com.sakata.focusflow§
§adb -s <serial> shell monkey -p com.sakata.focusflow 1§

再测真实重启（单独记状态）：

§adb -s <serial> reboot§
§adb wait-for-device§

解锁后检查顶层 Activity、通知渠道、未来提醒和旧广播是否重复。手工发送 TIMEZONE_CHANGED 只能验证广播处理，不等于真实重启通过。

### P2-B 最小外观/动画矩阵

先保存用户原设置，只测四个高信息量状态：

1. 默认纯色 + 动画标准；
2. 关闭“丰富的动画与外观效果” + 动画速度“关闭”；
3. 深色模式；
4. 窄屏或大字体（能切换时）。

每个状态返回今日、日程、计划、设置各一次，保存 UI XML/截图。观察底栏、页内弹窗、章节切换是否闪烁、跳变、出现矩形背景或被底栏遮挡。有 framestats 工具再采样慢帧；没有就写“未执行性能采样”。结束后恢复原设置。

### P2-C 一天连续使用

最后执行：覆盖安装保留数据、至少一次提醒、前后台切换、课程或重复任务变化、重启。检查无重复通知、无残留时间窗口、无自动导入。没有完整一天就写“未执行”。

### P2-A 精度记录

若 `SCHEDULE_EXACT_ALARM` 为 `default`，系统会使用不精确闹钟，实测提醒可能落在约 40–60 秒窗口内；只有显式授予精确闹钟权限后，才能验收分钟级精度。

## 2026-10-07 目标设备与 B-1 修复补充

本机原先按 ColorOS 16 / Android 15 记录，但测试设备已经系统升级；阶段 9 的目标基线随设备变更为该 OPPO 测试机的 ColorOS 17 / Android 17。上一轮通知、重启、外观、动画和稳定性证据仍然有效，均来自同一台设备。

Run 554 暴露的 B-1 是截图识别响应门禁过严：能力测试的六位数字 JSON 通过，并不能证明课表结构化响应包含每一个可选字段；旧客户端对缺少地点、周次、备注、置信度、坐标或候选 id 的响应整批拒绝。rc.29 的识别路径现在：

- 向模型提供完整的 JSON 形状示例和实际上传图片尺寸；
- 缺少可选字段时补为空值，仅在内存中进入审核；
- 缺少网格依据时保留课程名称，但星期/节次显示为待核对；
- 有坐标但与返回网格不一致时清空坐标并提示人工核对；
- 不会默认填周一/第 1 节，不会自动写入课程；
- 最终仍只有用户在审核页确认的候选才进入原有导入策略。

同机复测只需重跑 P1-B(截图导入) 和 P1-E；先确认识别完成并出现审核页，再执行 A 确认、B 编辑、C 拒绝。若仍失败，保留新的脱敏 shape 摘要和 UI XML，不删除原始课程数据。
