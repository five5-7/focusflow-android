# FocusFlow 9.0 发布范围说明

当前候选为 **9.0.0-rc.1 / versionCode 579**，正式发布仍为 8.2.1。本说明用于核对这次发布范围，工程验证和设备验收分别记录在 [发布前审计](9.0-release-audit-20261010.md) 与 [手动验收清单](9.0-manual-acceptance-20261010.md)。

## 日常功能

沿用记录 → 安排 → 提醒 → 完成/改期 → 保留历史的流程。收集箱、待办与计划、基础重复、活动记录、今日/明天视图、课程课次与提醒，以及删除撤回/回收站继续保留。核心记录不依赖 AI、地图或识别服务，相关可选功能只在主动使用时联网。

日程页保留日/周/固定课表，图例与时间轴分别占位；页签右侧显示当前范围。帮助问号统一在标题右侧，长标题在它左侧换行；提醒副页使用简短导航名。跳转和展开卡片提供按实际卡片尺寸计算的触摸反馈；图片背景、折叠与导航过渡继续使用统一外观和动画设置。上述最新 UI 仍需默认/大字号与图片背景真机复核，不声称掉帧问题已通过量化验证。

## 本轮稳定性与实用性修订

- 检查更新能识别同基号更高候选序号，并按版本选择可用 Release；草稿不作为更新。当前安装版本与可用发布版本分别显示，避免把旧正式版说成当前版本。
- APK 下载先写临时文件；中断、HTTP 错误和非 APK 内容不成为可安装结果，旧完整文件保留。连接与临时文件会清理，最终签名与安装仍由系统安装器检查。
- 今天和明天都无空档时，改期进入手动选择，不再指定可能冲突的明天 09:00。
- 快速记录通知受系统限制时安全退出，保留用户开关并在回到应用后再尝试；已关闭的服务不会因系统重建而续启。
- 启动快照无法安全读取时显示诊断并保留记录；本地崩溃记录在进程启动时安装，超长堆栈与旧大文件均受字节上限约束。
- 活动单日/每周范围使用本地日历边界，避免夏令时多算或漏算一小时。

## 数据与保留事项

覆盖安装沿用现有本地保存方式，任务、课程身份、历史及外观的数据契约不改。Room 新数据源激活仍关闭，不能将数据库设计与自动测试完成写成已经切换产品存储。应用内没有完整换机恢复入口；损坏保护、地点包和系统备份策略不能作为完整恢复能力的证明。

真实课表识别曾在当前目标设备失败，新的识别方案继续暂缓；原有入口、实现和校验门禁保留，失败不得自动写入课程。导入 dsh 与假期调课属于后续待实现功能，不是本次交接或已交付能力。

## 正式发布条件

候选必须通过 Debug/Release 回归、双构建、Room schema、版本、稳定签名和不可调试检查。维护者再核对覆盖安装数据、课程归组、提醒/真实重启、最新 UI，以及完整一天正常使用。已有约 25 分钟压缩切换证据只适用于旧候选；Keystore 失效与换机恢复尚无完整设备证据，需要在发布决定中明确记录剩余风险。

候选审核后，正式包仍需去掉 rc 后缀并再次增加 versionCode、执行完整 CI。合并、正式 tag 和 GitHub Release 在维护者明确批准后进行。
