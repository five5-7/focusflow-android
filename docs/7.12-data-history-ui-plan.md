# FocusFlow 7.12 数据管理与课程／空挡界面修整计划

状态：`7.12.0-rc.1` 已实现，等待自动构建与真机验收。

## 课程管理

- 批量管理增加“全选／取消全选”，作用范围必须是当前可见且可管理的已确认课程；全选后仍需二次确认才能删除。
- 修正课程卡片左右失衡：当前左侧通常只有课程名和节次／地点两行，右侧竖排“编辑／停用／删除”三个按钮，导致左侧上下留白明显。
- 优先评估把低频操作收进单一“更多”入口，或改成底部横向操作区；窄屏和大字体下不得拥挤，删除仍使用错误色并与普通操作分开。
- 批量模式沿用原卡片位置展示选择框、已选数量和全选状态，不另开难以返回的管理页。

## 空挡建议为 0 的诊断

“建议 0”不能直接当作没有空挡。开始实现前分别核对：

1. 是否存在已启用且处于生效期内的课程。
2. 是否生成课间空挡或不少于 60 分钟的自由时段。
3. 空挡是否被已有任务占用或被通勤时间扣除。
4. 是否没有可匹配的目标或弹性任务，导致有空挡但没有内容建议。
5. 校园生活、假期阶段、课程生效期或通勤兜底是否使输入被过滤。

界面需要区分“没有空挡”“有空挡但没有可推荐内容”“条件关闭／数据不足”，并给出就近下一步，不能统一只显示数字 0。

## 空挡课表视图

- 当前显示效果未通过验收，7.12 不做局部装饰修补，先对照日／周日程和固定课表重新审查信息层级。
- 明确视图的主要用途：看哪里有连续可用时间，而不是再复制一张普通课程表。
- 课程块保持次要，空挡区间成为主要视觉对象；清楚显示起止时间、净可用分钟和必要的通勤扣除。
- 避免过密网格、过小文字和依赖单一颜色；长课程名、窄屏、大字体、浅色／深色／自定义主题均需检查。
- 分类切换继续保留，但“课表”标签的数量应表达可理解的内容，不能用课程门数冒充空挡数量。

## 历史记录数据管理

- 支持单条删除、批量选择删除、全选／取消全选和一键清空。
- 一键清空必须明确数据范围并二次确认，不与“清空当前筛选结果”混淆。
- 删除后立即从剩余事件重新计算历史统计、完成率样本及相关摘要，不保留由已删除事件产生的旧结论。
- 课程删除继续不自动删除历史；历史清理只由用户在历史管理中主动执行。
- 如不同历史类型影响不同统计，确认弹窗应说明连带影响，不能只写“删除后不可恢复”。

## 统一验收

- 全选状态随当前可见集合变化正确更新；空列表、部分选择、全选、取消和删除后均无残留选择。
- 单删不会误删内容相同但 ID 不同的课程或历史记录。
- 课程卡片左右视觉重量平衡，常用操作易找，危险操作不易误触。
- “建议 0”能展示真实原因和下一步，而不是只给空结果。
- 空挡课表在目标设备上能优先回答“什么时候有多少可用时间”。
- 数据删除覆盖取消、写入失败、重启后持久化和统计重算测试。
- 完成自动测试后，仍需在 OPPO / ColorOS、窄屏、大字体和全部主题下真机验收。
