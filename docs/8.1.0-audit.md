## 一、结论摘要

- **数据契约**：既有 SharedPreferences 键与 JSON 字段**零改动**（`PrototypeStore` 在本会话只删过 1 行 import，新增的 `restored_boot_count` / `seen_boot_count` 均带默认值、只读写自己的键；`*Codec.kt`/`*Data.kt` 未出现在任何 diff 里）。
- **临时实验已清干净**：方案切换开关（`ExitScheme`）已彻底删除，`MotionScale` 回到只有 `durationScale`。
- **动画速度覆盖**：main 源码中已无裸 `tween(`，全部经 `MotionSpec` → `motionMillis`；0× 时全部退化为瞬时（单测覆盖）。
- **但存在 1 条会静默吞掉用户点击的严重回归**（本报告第二节，已真机复现），另有 5 条中等问题、16 条低优先问题。

## 二、严重（必修，用户可感）

### S1. 离开带子页的页签后，页面点击被静默吞掉约 400ms

- 位置：`MainActivity.kt:987`（`shrinkingOnTop`）、`990-996`（zIndex 2f）、`1008-1015`（消费型 pointerInput）、`420-425`（复位窗口）。
- 机理：收起中的隐藏页签被抬到 `zIndex(2f)`（可见页签只有 `1f`），同时它仍挂着 `pointerInput` 在 `Initial` 阶段消费所有指针事件；Compose 同级重叠命中只走最上层 → 收起期间页面上的点击先到它并被吞掉。`graphicsLayer` 只让命中区随缩放变小，**alpha=0 不关闭命中**。
- 复位窗口 `delay(MotionSpec.SUBPAGE_CROSS_MS + 80L)` 是**真实毫秒**，不随「外观 → 动画速度」缩放：0.5× 时动画 160ms 结束却仍挡 400ms；速度=关闭时动画瞬时，照样挡 400ms。
- **真机复现（release 包）**：
  ```
  计划·课程 → 点今日 → 立刻点「开始活动」   → 弹窗未打开（点击被吞）
  计划·课程 → 点今日 → 等 1.8s 再点同一位置 → 弹窗正常打开
  ```
- 修法：收起页签只负责绘制、不参与输入（`if (isVisibleTab || collapseLeaving) Modifier else Modifier.pointerInput…`）；复位窗口改用 `delay(motionMillis(SUBPAGE_CROSS_MS + 80))`；若要保留"缩小副页压在目标页之上"，改为 可见=2f / 收起=1f，靠副页层内部 `zIndex(1f)` 维持层级。

### S2. 弹窗打开时悬浮底栏完全不可用（8.1.0 新增交互与系统 Dialog 冲突）

- 位置：全部 53 处 `AlertDialog` 调用点。
- 机理：Android 的 `Dialog` 是**独立窗口**，永远盖在 Activity 之上，因此 8.1.0 的悬浮底栏（含回退／折返键）在弹窗期间既不可点、也不在无障碍树里（`uiautomator dump` 只能看到弹窗窗口）。底栏是 8.1.0 的核心交互，被弹窗整层盖住属于功能缺口。
- 真机确认：弹窗打开时 `uiautomator dump` 只有弹窗节点，无 `今日/日程/计划/设置`；点击底栏无响应。
- 修法：弹窗改**页内浮层**（`AppDialog.kt`），宿主挂在应用根、位于 `FloatingNavigationBar` 之前 → 弹窗永远在底栏之下，底栏保持可点；遮罩点击关闭、卡片自身吞掉点击、返回键关闭；弹窗期间页面内容 `clearAndSetSemantics`（与系统弹窗一致），底栏语义保留。
- 已决策（需维护者确认）：弹窗打开时点底栏切页签，弹窗作为**模态层保留**（不自动关闭）。理由：弹窗是应用级模态，用户可能正在填写；自动关闭会丢输入，且「误触页签就丢内容」比「弹窗浮在新页面上」更糟。用户可随时用返回键或点遮罩关闭。

## 四、低优先（16 条，摘要）

- `MainActivity.kt:409/419-421` 用字面量 `-1` 代替 `TabMotionRules.NO_TAB`。
- `TabMotionRules.kt:44` 的 `0.85f` 是规则文件里的魔法数 → 提到 `MotionSpec.JUMP_REST_SCALE`。
- `MainActivity.kt:952` 的 `80.dp/96.dp` 平动幅度硬编码 → 收进 MotionSpec/Layout。
- `MainActivity.kt:923` 注释"四个页签常驻组合（零重组）"已过期。
- `MainActivity.kt:933-944` 新页签在 `LaunchedEffect(tab)` 的**下一帧**才入 `visitedTabs` → 首次进入空白一帧；建议组合期 add。

- `MotionSpec.kt:25/31` 注释提到已不存在的"子页推入"；"选中态"实际用 `move()`。
- `MotionSpec.kt:43-47` `COLLAPSE_SCALE=0.12` 注释称"约等于底栏图标底色大小"，实际是 0.12×宽 × 0.12×高的竖条。
- `SubpageMotion.kt:91-96` 子页之间父子上退时，被收起的子页仍收向**底栏图标**（应为上一层父页中心）；设置 `CAMPUS_PLACES(3)→APPEARANCE(1)` 会走到。
- `SubpageMotion.kt:116` 组合期读 `transition.isRunning/currentState` 挂拦截层（基线已有）。
- `MainActivity.kt:1543-1548` 的 `hasSubpage` 与 `TabMotionRules.subpageOpenOn` 是同一规则两份实现 → 改调后者。
- 未使用 import：`MainActivity.kt` 约 35 个、`PlansScreen.kt` 约 50 个、`TodayScreen.kt`/`SettingsScreen.kt` 若干、`ScrollableContainers.kt:23`（均为基线遗留）。
- `NavKind` 的 `TAB/BACK/FORWARD` 只写不读（全仓只有 `== JUMP` 一处读）。
- `MotionScale.kt:22` `motionMillis` 唯一调用点是 `MotionSpec`。
- `FloatingNavigationBar.kt:351-354` `fill` 由动画中的 progress 算、`foreground` 再对它做 `animateColorAsState`，形成双层延迟，切换瞬间图标可能低对比。
- `MainActivity.kt:139-142` 冷启动返回兜底 `addCallback` 永不注销 → 若将来某状态无 Compose BackHandler，返回会被永久吞掉。

性能结论：热切换已达标（1.7% 重帧、最重 17–18ms）；每个页签**首次**显示仍有一次性 45–62ms
（约 3 帧），归因实验排除了"显示列表记录"这一解释，更像是该页首次合成/光栅化的一次性成本。

**子页转场专项（用户反馈"放大缩小有时掉帧"）**：进入/退出「课程」子页各 4 次，release 包实测

`requestedOrientation=SCREEN_ORIENTATION_PORTRAIT`。横屏几何修复保留为兜底（大屏/分屏被忽略锁定时）。
